## Overview

Chassis Tokens are built for iOS as Swift files. Each file declares its own type, a caseless enum with one constant per token:

```swift
import UIKit

public enum ChassisTokensColorLight {
    public static let ColorContextDefaultFgMain = UIColor(red: 0.086, green: 0.102, blue: 0.106, alpha: 1)
}

public enum ChassisTokens {
    public static let SpaceContextMedium = CGFloat(16)
    public static let TypographyFontFamilyText = "Inter"
}
```

Colours are `UIColor`, sizes and numbers are `CGFloat`, font weights are `UIFont.Weight`, and everything else is a `String`. The iOS files are in the npm package, under `node_modules/@chassis-ui/tokens/dist/ios/`, or build them from the repository.

## Generated Files

The build writes eight files to `dist/ios/<app>/<brand>/`. The configured iOS app is `demo`:

<CxTable>
| File | Type | Contents |
|------|------|----------|
| `ChassisTokens.swift` | `ChassisTokens` | Every token except theme colours, with the values of the light theme and the large screen |
| `String.swift` | `ChassisTokensString` | Font families, font weights, other strings and SVG icons |
| `Color.swift` | `ChassisTokensColor` | Theme colours that follow the light and dark appearance |
| `ColorLight.swift`, `ColorDark.swift` | `ChassisTokensColorLight`, `ChassisTokensColorDark` | Theme colours of one theme: context, primitive and component colours, and gradients |
| `NumberLarge.swift`, `NumberMedium.swift`, `NumberSmall.swift` | `ChassisTokensNumberLarge`, `ChassisTokensNumberMedium`, `ChassisTokensNumberSmall` | Sizes, spacing, numbers and opacities with the values of one screen size |
| `Icons.xcassets` | | The icons as vector image sets, next to their SVG text in `ChassisTokensString`; see [Icons](#icons) |
</CxTable>

Every file declares a different type, so all eight can be in one target. `ChassisTokens` repeats the tokens of `ChassisTokensString` and `ChassisTokensNumberLarge`, and the component colours of `ChassisTokensColorLight`. The string, colour and number types share no names with each other. Together they hold everything in `ChassisTokens` except the base colours (`ColorBase…`), which are the raw palette behind the context colours.

## Build the Tokens

Add the tokens repository to your project, for example as a Git submodule, and build the iOS files. The build needs Node.js 22 or later and pnpm:

```bash
git submodule add https://github.com/chassis-ui/tokens.git Submodules/ChassisTokens
cd Submodules/ChassisTokens
pnpm install
pnpm tokens --brand chassis --app demo --platform ios
```

The files are written to `Submodules/ChassisTokens/packages/tokens/dist/ios/demo/chassis/`. To build them for your own app, add it to `chassis.build.apps` in `packages/tokens/package.json` and give it token sets in `packages/tokens/tokens/$themes.json`; see [Style Dictionary]([[docsref:/getting-started/style-dictionary#build-options]]).

### Constant References

By default every constant holds its value. With the `outputReferences` option in `chassis.build` of `packages/tokens/package.json`, a constant names the constant of the token it references instead, which keeps the relationships of the design tokens visible in Swift:

```json
"options": { "ios": { "outputReferences": true } }
```

```swift
public static let SizeUnit4 = DimensionBase4
public static let ColorAccordionItemFgColor = ColorContextDefaultFgMain
```

The value of each constant is the same with and without the option. A constant names another only in the same file and only when both have the same Swift type and value; base colours, sizes computed with math and colours such as `rgba({colour}, {opacity})` print their values.

## Add the Tokens to Your App

Add the files you need to your app target, or all eight. Write the type before each token:

```swift
view.backgroundColor = ChassisTokensColor.ColorContextDefaultBgMain
stack.spacing = ChassisTokens.SpaceContextMedium
```

If your app needs one theme and one screen size, `ChassisTokens.swift` alone holds every token except the theme colours of the colour files and the other screen sizes.

To keep the files in the tokens repository, add a `Package.swift` to its root with one library for all files:

```swift
// swift-tools-version:5.9
import PackageDescription

let package = Package(
    name: "ChassisTokens",
    platforms: [.iOS(.v13)],
    products: [.library(name: "ChassisTokens", targets: ["ChassisTokens"])],
    targets: [
        .target(name: "ChassisTokens", path: "packages/tokens/dist/ios/demo/chassis", exclude: ["Icons.xcassets"])
    ]
)
```

In Xcode, choose **File → Add Package Dependencies… → Add Local…**, select the tokens repository and add the `ChassisTokens` library to your app target. Then `import ChassisTokens` in the files that use tokens. The package leaves out the icon catalog, which goes into the app target; see [Icons](#icons).

## Colours and Dark Mode

`ChassisTokensColor` in `Color.swift` holds every theme colour once. A colour that differs between the light and dark theme follows the interface style:

```swift
public static let ColorContextDefaultBgMain = UIColor { $0.userInterfaceStyle == .dark ? UIColor(red: 0.067, green: 0.075, blue: 0.078, alpha: 1) : UIColor(red: 1.000, green: 1.000, blue: 1.000, alpha: 1) }
```

Use these colours in views, and the appearance of each view picks the value:

```swift
import UIKit
import ChassisTokens

view.backgroundColor = ChassisTokensColor.ColorContextDefaultBgMain
label.textColor = ChassisTokensColor.ColorContextDefaultFgMain
```

`ChassisTokensColorLight` and `ChassisTokensColorDark` hold the colours of one theme each, for code that needs a fixed theme. The build writes `Color.swift` when the build options have a `light` and a `dark` theme; other themes have only their own file.

In SwiftUI, wrap a colour with `Color(uiColor:)` (iOS 15) or `Color(_:)`; the SwiftUI colour follows the appearance too:

```swift
import SwiftUI
import ChassisTokens

extension Color {
    static let bgMain = Color(uiColor: ChassisTokensColor.ColorContextDefaultBgMain)
    static let fgMain = Color(uiColor: ChassisTokensColor.ColorContextDefaultFgMain)
}
```

### SwiftUI Values

For an app written in SwiftUI, the `ios-swiftui` platform writes the same files with SwiftUI values, `Color` and `Font.Weight`, to `dist/ios-swiftui/<app>/<brand>/`:

```json
"apps": { "demo": ["ios", "ios-swiftui"] }
```

```swift
public static let ColorContextDefaultBgMain = Color(red: 1.000, green: 1.000, blue: 1.000, opacity: 1)
public static let TypographyFontWeightTextStrongWeight = Font.Weight.semibold
```

These colours have one theme each; for colours that follow the appearance, use `ChassisTokensColor` of the UIKit files as above. See [SwiftUI and Compose Presets]([[docsref:/getting-started/style-dictionary#swiftui-and-compose-presets]]).

### Gradients

A gradient token is split into its parts: the angle, and the colour and position of each stop.

```swift
public static let GradientPrimitiveBlackL000Angle = CGFloat(0)
public static let GradientPrimitiveBlackL000Stop1Color = UIColor(red: 0.000, green: 0.000, blue: 0.000, alpha: 0)
public static let GradientPrimitiveBlackL000Stop1Position = CGFloat(0)
public static let GradientPrimitiveBlackL000Stop2Color = UIColor(red: 0.000, green: 0.000, blue: 0.000, alpha: 1)
public static let GradientPrimitiveBlackL000Stop2Position = CGFloat(1)
```

The angle is the CSS angle in degrees: `0` points up and angles turn clockwise, so `90` runs from left to right. Positions go from `0` to `1`. Turn the parts into a `CAGradientLayer`:

```swift
import UIKit
import ChassisTokens

typealias Tokens = ChassisTokensColor

func applyGradient(to layer: CAGradientLayer, angle: CGFloat, stops: [(UIColor, CGFloat)]) {
    let radians = angle * .pi / 180
    let dx = sin(radians) / 2
    let dy = -cos(radians) / 2
    layer.startPoint = CGPoint(x: 0.5 - dx, y: 0.5 - dy)
    layer.endPoint = CGPoint(x: 0.5 + dx, y: 0.5 + dy)
    layer.colors = stops.map { $0.0.cgColor }
    layer.locations = stops.map { NSNumber(value: Double($0.1)) }
}

let fade = CAGradientLayer()
applyGradient(to: fade, angle: Tokens.GradientPrimitiveBlackL000Angle, stops: [
    (Tokens.GradientPrimitiveBlackL000Stop1Color, Tokens.GradientPrimitiveBlackL000Stop1Position),
    (Tokens.GradientPrimitiveBlackL000Stop2Color, Tokens.GradientPrimitiveBlackL000Stop2Position),
])
```

The start and end points follow the angle exactly in a square layer. In other shapes, CSS lengthens the gradient line so that the corners get the first and last colours, which these points do not.

## Icons

`Icons.xcassets` holds one image set per icon token, named like its constant, such as `IconChipRemove`. Each keeps its SVG as a vector and renders as a template, so it takes the tint colour, as `currentcolor` does on the web. Add the catalog to your app target, for example by dragging it into Xcode as a reference, and load an icon by name:

```swift
let remove = UIImage(named: "IconChipRemove")
button.setImage(remove, for: .normal)
button.tintColor = ChassisTokensColor.ColorContextDefaultFgMain
```

In SwiftUI, `Image("IconChipRemove")` takes the foreground style. Xcode compiles the catalog with its asset compiler.

## Sizes and Screen Sizes

Sizes are points, as `CGFloat`. Most sizes are the same on every screen; a few differ, such as `SizeWebsiteSectionIcon`: `80` on large, `64` on medium and `48` on small screens. Choose the number type for the current layout, for example by size class:

```swift
import UIKit
import ChassisTokens

func sectionIconSize(for traits: UITraitCollection) -> CGFloat {
    traits.horizontalSizeClass == .compact
        ? ChassisTokensNumberSmall.SizeWebsiteSectionIcon
        : ChassisTokensNumberLarge.SizeWebsiteSectionIcon
}
```

Which screen size matches which device is your choice.

## Typography

Typography tokens are split into one constant per property:

```swift
ChassisTokensString.FontContextLeadFontFamily         // "Inter"
ChassisTokensString.FontContextLeadFontWeight         // UIFont.Weight.regular
ChassisTokensNumberLarge.FontContextLeadFontSize      // 22
ChassisTokensNumberLarge.FontContextLeadLineHeight    // 32
ChassisTokensNumberLarge.FontContextLeadLetterSpacing // 0
```

- **Font family** is the first family of the stack. `UIFont(name:size:)` returns `nil` unless the app bundles and registers that font.
- **Font weight** is a `UIFont.Weight`, such as `.regular` or `.semibold`, which `UIFont.systemFont(ofSize:weight:)` takes. For a custom font, map the weight to a font file name. The design's weight names map as on the web: `Semi Bold` and `SemiBold` are both `.semibold`.
- **Line height** is in points. A design value in percent is converted with the font size of the same typography token: `FontContextJumboLineHeight` is `125%` of `96`, so `120`.
- **Letter spacing** is in points.

## Shadows and Opacity

Shadow tokens are split into their parts, with the CSS meaning of each, and one part for Core Animation: `…Radius`, half the CSS blur, which is about the same shadow as `shadowRadius`.

```swift
public static let ShadowContextSmall1Blur = CGFloat(8)
public static let ShadowContextSmall1Radius = CGFloat(4)
```

The colour carries the shadow's opacity. Core Animation multiplies it by `shadowOpacity`, so set that to `1`:

```swift
import UIKit
import ChassisTokens

func applySmallShadow(to layer: CALayer) {
    layer.shadowColor = ChassisTokensColor.ShadowContextSmall1Color.cgColor
    layer.shadowOpacity = 1
    layer.shadowOffset = CGSize(
        width: ChassisTokensNumberLarge.ShadowContextSmall1OffsetX,
        height: ChassisTokensNumberLarge.ShadowContextSmall1OffsetY
    )
    layer.shadowRadius = ChassisTokensNumberLarge.ShadowContextSmall1Radius
}
```

`cgColor` takes the value of the current appearance, and many shadow colours are darker in dark mode, so apply the shadow again when the trait collection changes. Core Animation shadows have no spread. Opacity tokens are fractions, such as `OpacityLevel40` (`0.4`).

## Best Practices

✅ **Prefer context tokens**: Use `ColorContext…`, `SpaceContext…` and `BorderRadiusContext…` over base and primitive tokens.

✅ **Name tokens in one place**: Wrap the tokens you use in extensions, such as `UIColor.bgMain = ChassisTokensColor.ColorContextDefaultBgMain`, so views do not depend on the token types.

✅ **Change tokens at the source**: Chassis Tokens is meant to be owned and customized. Change values in Tokens Studio and rebuild, instead of editing the generated files.

✅ **Test both appearances**: Check every screen in light and dark mode.

❌ **Don't mix screen sizes by accident**: `ChassisTokens` holds the values of the large screen. Use a `ChassisTokensNumber…` type where a size depends on the screen.

## Troubleshooting

### Invalid Redeclaration of 'ChassisTokens'

The files come from a build before each file had its own type, when all of them declared `ChassisTokens`, or one file is in the target twice. Rebuild the tokens and add each file once.

### Cannot Find 'ChassisTokensColorLight' in Scope

The file is not in the target, or the package module is not imported. Add the file, or `import ChassisTokens`.

### Cannot Find a Token

Check the name in the generated file. Names are PascalCase without a prefix, such as `SpaceContextMedium`. Context colours are in the colour types only: `ChassisTokensColor`, `ChassisTokensColorLight` and `ChassisTokensColorDark`.

## Continuous Integration

Build the tokens before the app. The build needs Node.js 22 or later:

```yaml
# .github/workflows/build.yml
name: Build iOS App

on: [push]

jobs:
  build:
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v5
        with:
          submodules: recursive

      - uses: pnpm/action-setup@v6

      - uses: actions/setup-node@v5
        with:
          node-version: '22'

      - name: Build tokens
        working-directory: Submodules/ChassisTokens
        run: |
          pnpm install
          pnpm tokens --brand chassis --app demo --platform ios

      - name: Build app
        run: xcodebuild -project YourApp.xcodeproj -scheme YourApp build
```
