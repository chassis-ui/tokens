## Overview

Chassis Tokens are built for iOS as Swift files. Each file declares a class `ChassisTokens` with one constant per token:

```swift
import UIKit

public class ChassisTokens {
    @objc public static let ColorContextDefaultFgMain = UIColor(red: 0.086, green: 0.102, blue: 0.106, alpha: 1)
    @objc public static let SpaceContextMedium = CGFloat(16)
    @objc public static let TypographyFontFamilyText = "Inter"
}
```

Colours are `UIColor`, sizes and numbers are `CGFloat`, and everything else is a `String`. The iOS files are not in the npm package; build them from the repository.

## Generated Files

The build writes seven files to `dist/ios/<app>/<brand>/`. The configured iOS app is `demo`:

<CxTable>
| File | Contents |
|------|----------|
| `Main.swift` | Every token except theme colours, with the values of the light theme and the large screen |
| `String.swift` | Font families, font weights, other strings and SVG icons |
| `ColorLight.swift`, `ColorDark.swift` | Theme colours: context, primitive and component colours, and gradients |
| `NumberLarge.swift`, `NumberMedium.swift`, `NumberSmall.swift` | Sizes, spacing, numbers and opacities with the values of one screen size |
</CxTable>

<Callout type="warning">
Every file declares the same class, `ChassisTokens`, so two of them cannot be in one Swift module: the compiler reports `invalid redeclaration of 'ChassisTokens'`. Add one file to your app target, or give each file its own module as described below.
</Callout>

`Main.swift` holds the tokens of `String.swift` and the large number file, and the component colours of the light colour file. The string, colour and number files share no names with each other. Together they hold everything in `Main.swift` except the base colours (`ColorBase…`), which are the raw palette behind the context colours.

## Build the Tokens

Add the tokens repository to your project, for example as a Git submodule, and build the iOS files. The build needs Node.js 22 or later and pnpm:

```bash
git submodule add https://github.com/chassis-ui/tokens.git Submodules/ChassisTokens
cd Submodules/ChassisTokens
pnpm install
pnpm tokens --brand chassis --app demo --platform ios
```

The files are written to `Submodules/ChassisTokens/dist/ios/demo/chassis/`. To build them for your own app, add it to `chassis.build.apps` in `package.json` and give it token sets in `tokens/$themes.json`; see [Style Dictionary]([[docsref:/getting-started/style-dictionary#build-options]]).

## Add the Tokens to Your App

### One File

If your app needs one theme and one screen size, add `Main.swift` to your app target. It holds every token except the dark colours and the other screen sizes:

```swift
view.backgroundColor = ChassisTokens.ColorButtonPrimaryBgIdle
stack.spacing = ChassisTokens.SpaceContextMedium
```

`Main.swift` does not have the context colours (`ColorContext…`); those are in the colour files.

### One Module per File

For light and dark colours, or several screen sizes, give each file its own module with a Swift package. Add a `Package.swift` to the root of your tokens repository:

```swift
// swift-tools-version:5.9
import PackageDescription

let tokens = "dist/ios/demo/chassis"

// One module per generated file, because every file declares `ChassisTokens`
let modules = [
    ("ChassisTokensString", "String.swift"),
    ("ChassisTokensLight", "ColorLight.swift"),
    ("ChassisTokensDark", "ColorDark.swift"),
    ("ChassisTokensLarge", "NumberLarge.swift"),
    ("ChassisTokensMedium", "NumberMedium.swift"),
    ("ChassisTokensSmall", "NumberSmall.swift"),
]

let package = Package(
    name: "ChassisTokens",
    platforms: [.iOS(.v13)],
    products: modules.map { .library(name: $0.0, targets: [$0.0]) },
    targets: modules.map { .target(name: $0.0, path: tokens, sources: [$0.1]) }
)
```

In Xcode, choose **File → Add Package Dependencies… → Add Local…**, select the tokens repository and add the libraries you need to your app target.

`Main.swift` is left out on purpose: Swift Package Manager treats a file named `Main.swift` as the entry point of an executable, so it cannot be a library target. The string, colour and number modules hold all of its tokens except the base colours.

Import the modules and write the module name before `ChassisTokens`. Without it, the name is ambiguous:

```swift
import ChassisTokensLight
import ChassisTokensLarge

let background = ChassisTokensLight.ChassisTokens.ColorContextDefaultBgMain
let padding = ChassisTokensLarge.ChassisTokens.SpaceContextMedium
```

## Colours and Dark Mode

The light and dark colour files declare the same names with different values. Combine them into dynamic colours that follow the interface style:

```swift
import UIKit
import ChassisTokensLight
import ChassisTokensDark

typealias Light = ChassisTokensLight.ChassisTokens
typealias Dark = ChassisTokensDark.ChassisTokens

extension UIColor {
    static func token(light: UIColor, dark: UIColor) -> UIColor {
        UIColor { traits in traits.userInterfaceStyle == .dark ? dark : light }
    }

    static let bgMain = token(light: Light.ColorContextDefaultBgMain, dark: Dark.ColorContextDefaultBgMain)
    static let fgMain = token(light: Light.ColorContextDefaultFgMain, dark: Dark.ColorContextDefaultFgMain)
    static let primaryBg = token(light: Light.ColorContextPrimaryBgSolid, dark: Dark.ColorContextPrimaryBgSolid)
    static let primaryFg = token(light: Light.ColorContextPrimaryFgSolid, dark: Dark.ColorContextPrimaryFgSolid)
}
```

Use them in UIKit, or in SwiftUI through `Color(uiColor:)` (iOS 15) or `Color(_:)`:

```swift
import SwiftUI

extension Color {
    static let bgMain = Color(uiColor: .bgMain)
    static let fgMain = Color(uiColor: .fgMain)
}
```

Gradient tokens (`GradientPrimitive…`) hold only the first colour stop of the gradient.

## Sizes and Screen Sizes

Sizes are points, as `CGFloat`. Most sizes are the same on every screen; a few differ, such as `SizeWebsiteSectionIcon`: `80` on large, `64` on medium and `48` on small screens. Choose the module for the current layout, for example by size class:

```swift
import UIKit
import ChassisTokensLarge
import ChassisTokensSmall

func sectionIconSize(for traits: UITraitCollection) -> CGFloat {
    traits.horizontalSizeClass == .compact
        ? ChassisTokensSmall.ChassisTokens.SizeWebsiteSectionIcon
        : ChassisTokensLarge.ChassisTokens.SizeWebsiteSectionIcon
}
```

Which screen size matches which device is your choice.

## Typography

Typography tokens are split into one constant per property:

```swift
ChassisTokensString.ChassisTokens.FontContextLeadFontFamily      // "Inter"
ChassisTokensString.ChassisTokens.FontContextLeadFontWeight      // "regular"
ChassisTokensLarge.ChassisTokens.FontContextLeadFontSize         // 22
ChassisTokensLarge.ChassisTokens.FontContextLeadLineHeight       // 32
ChassisTokensLarge.ChassisTokens.FontContextLeadLetterSpacing    // 0
```

- **Font family** is the first family of the stack. `UIFont(name:size:)` returns `nil` unless the app bundles and registers that font.
- **Font weight** is a name such as `"regular"` or `"semi-bold"`, not a `UIFont.Weight`. Map the names your app uses to weights or to font file names.
- **Line height** is in points, except in tokens whose design value is a percentage: those print the percentage as a number, such as `125`.
- **Letter spacing** is in points.

## Shadows and Opacity

Shadow tokens are split into their parts:

```swift
import UIKit
import ChassisTokensLight
import ChassisTokensLarge

func applySmallShadow(to layer: CALayer) {
    let color = ChassisTokensLight.ChassisTokens.ShadowContextSmall1Color
    layer.shadowColor = color.withAlphaComponent(1).cgColor
    layer.shadowOpacity = Float(color.cgColor.alpha)
    layer.shadowOffset = CGSize(
        width: ChassisTokensLarge.ChassisTokens.ShadowContextSmall1OffsetX,
        height: ChassisTokensLarge.ChassisTokens.ShadowContextSmall1OffsetY
    )
    layer.shadowRadius = ChassisTokensLarge.ChassisTokens.ShadowContextSmall1Blur / 2
}
```

Core Animation shadows have no spread, and their radius is about half of a CSS blur. Opacity tokens are fractions, such as `OpacityLevel40` (`0.4`).

## Best Practices

✅ **Prefer context tokens**: Use `ColorContext…`, `SpaceContext…` and `BorderRadiusContext…` over base and primitive tokens.

✅ **Name tokens in one place**: Wrap the tokens you use in extensions, such as `UIColor.bgMain`, so views do not depend on module names.

✅ **Change tokens at the source**: Chassis Tokens is meant to be owned and customized. Change values in Tokens Studio and rebuild, instead of editing the generated files.

✅ **Test both appearances**: Check every screen in light and dark mode.

❌ **Don't add several token files to one target**: They all declare `ChassisTokens`.

## Troubleshooting

### Invalid Redeclaration of 'ChassisTokens'

Two generated files are in one module. Keep one file per module, as in [One Module per File](#one-module-per-file).

### Ambiguous Use of 'ChassisTokens'

Several token modules are imported. Write the module name first: `ChassisTokensLight.ChassisTokens.ColorContextDefaultBgMain`.

### Library Product Should Not Contain Executable Targets

A package target contains `Main.swift`, which Swift Package Manager treats as an executable entry point. Use the string, colour and number files in packages, or add `Main.swift` directly to an app target.

### Cannot Find a Token

Check the name in the generated file. Names are PascalCase without a prefix, such as `SpaceContextMedium`. Context colours are in the colour files only.

### A Token Name Differs on Small Screens

In the current tokens, one spacing token has another name in `NumberSmall.swift`: `SpaceWebsiteContentHeadersGap` instead of `SpaceWebsiteContentHeaderGap`. The name comes from the token source and needs to be fixed there.

## Continuous Integration

Build the tokens before the app. The build needs Node.js 22 or later:

```yaml
# .github/workflows/build.yml
name: Build iOS App

on: [push]

jobs:
  build:
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v5
        with:
          submodules: recursive

      - uses: pnpm/action-setup@v6

      - uses: actions/setup-node@v5
        with:
          node-version: '22'

      - name: Build tokens
        working-directory: Submodules/ChassisTokens
        run: |
          pnpm install
          pnpm tokens --brand chassis --app demo --platform ios

      - name: Build app
        run: xcodebuild -project YourApp.xcodeproj -scheme YourApp build
```
