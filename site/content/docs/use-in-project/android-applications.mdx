## Overview

Chassis Tokens are built for Android as XML resource files, one resource per token:

```xml
<resources>
  <color name="color_context_default_fg_main">#ff161a1b</color>
  <dimen name="space_context_medium">16dp</dimen>
  <dimen name="font_context_lead_font_size">22sp</dimen>
  <item name="opacity_level_40" type="dimen" format="float">0.4</item>
  <string name="typography_font_family_text">Inter</string>
</resources>
```

<CxTable>
| Tokens | Resource | Example |
|--------|----------|---------|
| Colours | `color`, ARGB hex | `#ff00a4cc` |
| Font sizes, line heights, paragraph spacing | `dimen` in `sp` | `22sp` |
| Other sizes and spacing | `dimen` in `dp` | `16dp` |
| Opacity and letter spacing | `dimen` float item | `0.4` |
| Font weights | `integer`, 100 to 900 | `600` |
| Other whole numbers | `integer` | none in the current tokens |
| Font families, other strings and SVG icons | `string`, escaped | `Inter` |
</CxTable>

Names are snake_case without a prefix, such as `space_context_medium`. The Android files are not in the npm package; build them from the repository.

## Generated Files

The build writes seven files to `dist/android/<app>/<brand>/`. The configured Android app is `demo`:

<CxTable>
| File | Contents |
|------|----------|
| `main.xml` | Every token except theme colours, with the values of the light theme and the large screen |
| `string.xml` | Font families, font weights, other strings and SVG icons |
| `color_light.xml`, `color_dark.xml` | Theme colours: context, primitive and component colours, and gradients |
| `number_large.xml`, `number_medium.xml`, `number_small.xml` | Sizes, spacing, numbers and opacities with the values of one screen size |
</CxTable>

<Callout type="warning">
Do not put `main.xml` in one resource folder with the other files. It declares the resources of `string.xml` and the large number file, and the component colours of the light colour file, some with other values, so the build fails with `has a conflicting value`.
</Callout>

The string, colour and number files share no names with each other. Together they hold everything in `main.xml` except the base colours (`color_base_*`), which are the raw palette behind the context colours.

## Build the Tokens

Add the tokens repository to your project, for example as a Git submodule, and build the Android files. The build needs Node.js 22 or later and pnpm:

```bash
git submodule add https://github.com/chassis-ui/tokens.git submodules/chassis-tokens
cd submodules/chassis-tokens
pnpm install
pnpm tokens --brand chassis --app demo --platform android
```

The files are written to `submodules/chassis-tokens/dist/android/demo/chassis/`. To build them for your own app, add it to `chassis.build.apps` in `package.json` and give it token sets in `tokens/$themes.json`; see [Style Dictionary]([[docsref:/getting-started/style-dictionary#build-options]]).

## Add the Tokens to Your App

### One File

If your app needs one theme and one screen size, copy `main.xml` to `app/src/main/res/values/`. It holds every token except the dark colours, the other screen sizes and the context colours (`color_context_*`), which are in the colour files only.

### Resource Qualifiers

For dark mode and several screen sizes, copy the string, colour and number files into resource folders with qualifiers. Android picks the values for the current configuration:

```
app/src/main/res/
├── values/
│   ├── color_light.xml
│   ├── number_small.xml
│   └── string.xml
├── values-night/
│   └── color_dark.xml
├── values-sw600dp/
│   └── number_medium.xml
└── values-sw840dp/
    └── number_large.xml
```

The colour files declare the same names, and so do the number files, so each folder overrides the default values. Which screen size matches which qualifier is your choice.

A script keeps the folders up to date after each build:

```bash
#!/bin/sh
# scripts/sync-tokens.sh
set -e
TOKENS=submodules/chassis-tokens/dist/android/demo/chassis
RES=app/src/main/res

mkdir -p "$RES/values" "$RES/values-night" "$RES/values-sw600dp" "$RES/values-sw840dp"
cp "$TOKENS/color_light.xml" "$TOKENS/number_small.xml" "$TOKENS/string.xml" "$RES/values/"
cp "$TOKENS/color_dark.xml" "$RES/values-night/"
cp "$TOKENS/number_medium.xml" "$RES/values-sw600dp/"
cp "$TOKENS/number_large.xml" "$RES/values-sw840dp/"
```

## Use Tokens in XML

```xml
<!-- res/layout/card.xml -->
<com.google.android.material.card.MaterialCardView
    xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:app="http://schemas.android.com/apk/res-auto"
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    app:cardBackgroundColor="@color/color_context_default_bg_main"
    app:cardCornerRadius="@dimen/border_radius_context_medium">

    <TextView
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:padding="@dimen/space_context_medium"
        android:text="@string/app_name"
        android:textColor="@color/color_context_default_fg_main"
        android:textSize="@dimen/font_context_lead_font_size" />

</com.google.android.material.card.MaterialCardView>
```

## Use Tokens in Kotlin

```kotlin
import android.content.Context
import androidx.core.content.ContextCompat
import androidx.core.content.res.ResourcesCompat

fun readTokens(context: Context) {
    val background = ContextCompat.getColor(context, R.color.color_context_default_bg_main)
    val padding = context.resources.getDimensionPixelSize(R.dimen.space_context_medium)
    val opacity = ResourcesCompat.getFloat(context.resources, R.dimen.opacity_level_40)
    val family = context.getString(R.string.typography_font_family_text)
}
```

Opacity and letter spacing are float resources: read them with `ResourcesCompat.getFloat`, or with `Resources.getFloat` on API 29 and later.

## Use Tokens in Jetpack Compose

```kotlin
import androidx.compose.foundation.background
import androidx.compose.foundation.layout.padding
import androidx.compose.foundation.shape.RoundedCornerShape
import androidx.compose.material3.Text
import androidx.compose.runtime.Composable
import androidx.compose.ui.Modifier
import androidx.compose.ui.platform.LocalContext
import androidx.compose.ui.res.colorResource
import androidx.compose.ui.res.dimensionResource
import androidx.core.content.res.ResourcesCompat

@Composable
fun Card(text: String) {
    val subtle = ResourcesCompat.getFloat(LocalContext.current.resources, R.dimen.opacity_level_40)

    Text(
        text = text,
        color = colorResource(R.color.color_context_default_fg_main).copy(alpha = subtle),
        modifier = Modifier
            .background(
                colorResource(R.color.color_context_default_bg_main),
                RoundedCornerShape(dimensionResource(R.dimen.border_radius_context_medium))
            )
            .padding(dimensionResource(R.dimen.space_context_medium))
    )
}
```

Compose has no float resource function, so read float resources through `ResourcesCompat.getFloat`.

## Typography

Typography tokens are split into one resource per property:

```xml
<string name="font_context_lead_font_family">Inter</string>
<integer name="font_context_lead_font_weight">400</integer>
<dimen name="font_context_lead_font_size">22sp</dimen>
<dimen name="font_context_lead_line_height">32sp</dimen>
<item name="font_context_lead_letter_spacing" type="dimen" format="float">0</item>
```

- **Font family** is the first family of the stack. Map it to a font resource that your app bundles.
- **Font weight** is a number from 100 to 900, such as `400` or `600`. Compose takes it as `FontWeight(integerResource(R.integer.font_context_lead_font_weight))`, and `Typeface.create(family, weight, italic)` takes it on API 28 and later. The design's weight names map as on the web: `Semi Bold` and `SemiBold` are both `600`.
- **Line height** is in `sp`. A design value in percent is converted with the font size of the same typography token: `font_context_jumbo_line_height` is `125%` of `96`, so `120sp`.
- **Letter spacing** of a typography token is in ems of its font size, which `TextView.setLetterSpacing` and `android:letterSpacing` take; in Compose, use `value.em`. `font_context_jumbo_letter_spacing` is `-0.0052`: `-0.5` design pixels at `96`. The letter spacing scale (`typography_letter_spacing_*`) has no font size and stays in design pixels.

## Shadows

Shadow tokens are split into their parts, such as `shadow_context_small_1_offset_y` (`2dp`), `shadow_context_small_1_blur` (`8dp`), `shadow_context_small_1_spread` (`-2dp`) and `shadow_context_small_1_color` (`#1a000000`). Android elevation shadows do not take these parts; use them for custom drawing, or choose an elevation that looks close.

## Gradients

A gradient token is split into its parts: the angle and the colour and position of each stop.

```xml
<item name="gradient_primitive_black_l_000_angle" type="dimen" format="float">0</item>
<color name="gradient_primitive_black_l_000_stop_1_color">#00000000</color>
<item name="gradient_primitive_black_l_000_stop_1_position" type="dimen" format="float">0</item>
<color name="gradient_primitive_black_l_000_stop_2_color">#ff000000</color>
<item name="gradient_primitive_black_l_000_stop_2_position" type="dimen" format="float">1</item>
```

The angle is the CSS angle in degrees: `0` points up and angles turn clockwise, so `90` runs from left to right. Positions go from `0` to `1`. In Compose, build a brush from the parts once the size is known:

```kotlin
fun gradientBrush(angle: Float, stops: Array<Pair<Float, Color>>, size: Size): Brush {
    val radians = Math.toRadians(angle.toDouble())
    val half = Offset((sin(radians) * size.width / 2).toFloat(), (-cos(radians) * size.height / 2).toFloat())
    val center = Offset(size.width / 2, size.height / 2)
    return Brush.linearGradient(*stops, start = center - half, end = center + half)
}
```

Read the angle and positions with `ResourcesCompat.getFloat` and the colours with `colorResource`. The token angles are multiples of 45°, so a `GradientDrawable` with the matching `Orientation` works in views: `0` is `BOTTOM_TOP`, `90` is `LEFT_RIGHT`, `180` is `TOP_BOTTOM` and `270` is `RIGHT_LEFT`.

## Known Limitations

- **Icons**: SVG icon tokens (`icon_*`) are strings that hold SVG markup, such as `getString(R.string.icon_accordion_indicator)`. Android cannot draw an SVG string directly: render it with an SVG library, or use vector drawables for icons.

## Best Practices

✅ **Prefer context tokens**: Use `color_context_*`, `space_context_*` and `border_radius_context_*` over base and primitive tokens.

✅ **Use resource qualifiers**: Let Android pick the dark colours and the screen sizes, instead of choosing values in code.

✅ **Change tokens at the source**: Chassis Tokens is meant to be owned and customized. Change values in Tokens Studio and rebuild, instead of editing the generated files.

✅ **Test both themes**: Check every screen in light and dark mode.

❌ **Don't combine main.xml with the other files** in one resource folder.

## Troubleshooting

### Resource Has a Conflicting Value

`main.xml` is in a resource folder with a string, colour or number file. Use either `main.xml` alone or the other files, as in [Resource Qualifiers](#resource-qualifiers).

### Unresolved Reference to a Resource

Check the name in the generated file. Names are snake_case without a prefix, such as `color_context_default_bg_main`. Context colours are in the colour files only.

### Invalid Integer

Opacity and letter spacing are float items. Files built before this change printed them as `integer` resources, which Android rejects when the value is a fraction. Rebuild the tokens.

### Resources$NotFoundException

A resource exists only in a qualified folder, such as `values-sw600dp`, and the app runs in a configuration without it. Every resource needs a value in `values/`.

## Continuous Integration

Build the tokens and copy them before the app. The build needs Node.js 22 or later:

```yaml
# .github/workflows/android.yml
name: Build Android App

on: [push]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
        with:
          submodules: recursive

      - uses: pnpm/action-setup@v6

      - uses: actions/setup-node@v5
        with:
          node-version: '22'

      - name: Build tokens
        working-directory: submodules/chassis-tokens
        run: |
          pnpm install
          pnpm tokens --brand chassis --app demo --platform android

      - name: Copy tokens
        run: sh scripts/sync-tokens.sh

      - uses: actions/setup-java@v5
        with:
          distribution: 'temurin'
          java-version: '21'

      - name: Build app
        run: ./gradlew assembleDebug
```
