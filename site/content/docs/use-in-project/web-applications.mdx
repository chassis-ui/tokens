## Overview

Chassis Tokens are built for the web as SCSS variables. Each token is one `!default` variable, such as `$cx-space-context-medium: 1rem !default;`. The files hold variables only, so loading them adds nothing to your CSS until you use a variable.

There are two kinds of web output:

- **For Chassis CSS** (the default `web` platform): many values are CSS custom properties that [Chassis CSS](https://github.com/chassis-ui/css) defines, such as `var(--default-fg-main)`. Use this output together with Chassis CSS.
- **For other CSS frameworks** (the `web-scss`, `web-px` and `web-vw` presets): every value is resolved, such as `#161a1b`. Use this output when your project does not load Chassis CSS. See [presets for other CSS frameworks]([[docsref:/getting-started/style-dictionary#presets-for-other-css-frameworks]]).

The npm package contains the default output. To use a preset, build the tokens yourself from the repository.

## Installation

Install the Chassis Tokens package from npm:

```bash
npm install @chassis-ui/tokens
```

Or using other package managers:

```bash
# pnpm
pnpm add @chassis-ui/tokens

# yarn
yarn add @chassis-ui/tokens

# bun
bun add @chassis-ui/tokens
```

Your build also needs a Sass compiler, such as `sass` or `sass-embedded`:

```bash
npm install --save-dev sass
```

## Package Contents

The package contains the web output of the `docs` app for the `chassis` and `sinefil` brands:

```
node_modules/@chassis-ui/tokens/
└── dist/
    └── web/
        └── docs/
            ├── chassis/
            │   ├── main.scss
            │   ├── string.scss
            │   ├── color-light.scss
            │   ├── color-dark.scss
            │   ├── number-large.scss
            │   ├── number-medium.scss
            │   └── number-small.scss
            └── sinefil/
                └── ...
```

<CxTable>
| File | Contents |
|------|----------|
| `main.scss` | Every token except theme colours: base and component colours, sizes, spacing, border radii and widths, opacities, typography, shadows and strings. Sizes have the values of the large screen |
| `string.scss` | Font families, font weights and other strings, and SVG icons |
| `color-light.scss`, `color-dark.scss` | Theme colours: context, primitive and component colours, and gradients |
| `number-large.scss`, `number-medium.scss`, `number-small.scss` | Sizes, spacing, numbers and opacities with the values of one screen size |
</CxTable>

Where a token is declared matters when you use it:

- **Context colours** (`$cx-color-context-*`) are in the colour files only.
- **Sizes and spacing** are in `main.scss` and in each number file.
- **Component colours** are in `main.scss` and in each colour file.
- **`$prefix`** (`cx-`) is declared in every file. It holds the prefix of the variable names; changing it does not rename the variables.
- **Typography maps** (`$cx-font-*`) are in `main.scss`.

## Load Tokens with @use

Load each file as a Sass module with `@use` and give it a namespace:

```scss
@use "@chassis-ui/tokens/dist/web/docs/chassis/main" as tokens;
@use "@chassis-ui/tokens/dist/web/docs/chassis/color-light" as color;

.card {
  padding: tokens.$cx-space-context-medium;
  border-radius: tokens.$cx-border-radius-context-medium;
  background: color.$cx-color-context-default-bg-main;
  color: color.$cx-color-context-default-fg-main;
}
```

Compiled CSS:

```css
.card {
  padding: 1rem;
  border-radius: 0.375rem;
  background: #ffffff;
  color: #161a1b;
}
```

Namespaces keep files with the same variable names apart, which is what [themes](#themes) and [screen sizes](#screen-sizes) need.

<Callout type="info">
`@import` also loads the files, but it is deprecated and will be removed in Dart Sass 3. It puts every variable in one global scope, and because each variable is declared with `!default`, the first file that declares a name wins. Importing `color-dark.scss` after `color-light.scss`, even inside a selector or media query, keeps the light values.
</Callout>

### Values for Chassis CSS

In the default output, tokens that reference a Chassis CSS value print its custom property:

```scss
@use "@chassis-ui/tokens/dist/web/docs/chassis/main" as tokens;

.accordion-item {
  color: tokens.$cx-color-accordion-item-fg-color;
  border-radius: tokens.$cx-border-radius-accordion-main;
}
```

```css
.accordion-item {
  color: var(--default-fg-main);
  border-radius: var(--border-radius-md);
}
```

These values work on a page that loads Chassis CSS, which defines the custom properties. Without Chassis CSS, use a preset for other CSS frameworks, or use context tokens, which print resolved values in the default output too.

## Typography

Typography tokens are Sass maps whose keys are CSS property names. A map is not a valid CSS value, so `font: tokens.$cx-font-context-lead` fails. Read one property with `map.get`, or write all of them with `@each`:

```scss
@use "sass:map";
@use "@chassis-ui/tokens/dist/web/docs/chassis/main" as tokens;

@mixin text-style($style) {
  @each $property, $value in $style {
    #{$property}: $value;
  }
}

.lead {
  @include text-style(tokens.$cx-font-context-lead);
}

.caption {
  font-size: map.get(tokens.$cx-font-context-lead, "font-size");
}
```

Each map has the keys `font-family`, `font-weight`, `font-size`, `line-height`, `font-style`, `letter-spacing`, `margin-bottom`, `text-transform` and `text-decoration`. In the default output, family and weight are Chassis CSS custom properties, and so are size and line height when they reference a font size or line height token, such as `var(--font-size-text-xl)`. In the presets every part is a resolved value.

## Themes

`color-light.scss` and `color-dark.scss` declare the same variable names with different values. Load both with their own namespace and write the colours as CSS custom properties under your own theme selectors. This example uses a `data-theme` attribute on the root element; choose any selector your app uses:

```scss
@use "@chassis-ui/tokens/dist/web/docs/chassis/color-light" as light;
@use "@chassis-ui/tokens/dist/web/docs/chassis/color-dark" as dark;

:root {
  --app-bg: #{light.$cx-color-context-default-bg-main};
  --app-fg: #{light.$cx-color-context-default-fg-main};
}

[data-theme="dark"] {
  --app-bg: #{dark.$cx-color-context-default-bg-main};
  --app-fg: #{dark.$cx-color-context-default-fg-main};
}

body {
  background: var(--app-bg);
  color: var(--app-fg);
}
```

Compiled CSS:

```css
:root {
  --app-bg: #ffffff;
  --app-fg: #161a1b;
}

[data-theme=dark] {
  --app-bg: #111314;
  --app-fg: #e9eced;
}

body {
  background: var(--app-bg);
  color: var(--app-fg);
}
```

To write a whole group of tokens at once, loop over the variables of a module with `meta.module-variables`. This writes every context colour of each theme as a custom property named after its token, such as `--cx-color-context-default-bg-main`:

```scss
@use "sass:meta";
@use "sass:string";
@use "@chassis-ui/tokens/dist/web/docs/chassis/color-light" as light;
@use "@chassis-ui/tokens/dist/web/docs/chassis/color-dark" as dark;

@mixin context-colors($module) {
  @each $name, $value in meta.module-variables($module) {
    @if string.index($name, "cx-color-context-") == 1 {
      --#{$name}: #{$value};
    }
  }
}

:root {
  @include context-colors("light");
}

[data-theme="dark"] {
  @include context-colors("dark");
}
```

Switch the theme by setting the attribute:

```javascript
const root = document.documentElement;
const query = window.matchMedia('(prefers-color-scheme: dark)');

function setTheme(theme) {
  root.setAttribute('data-theme', theme);
  localStorage.setItem('theme', theme);
}

// Restore the saved theme, or follow the system setting
setTheme(localStorage.getItem('theme') || (query.matches ? 'dark' : 'light'));

// Toggle
function toggleTheme() {
  setTheme(root.getAttribute('data-theme') === 'dark' ? 'light' : 'dark');
}
```

## Screen Sizes

The number files declare the same variable names with the values of one screen size. `main.scss` has the values of the large screen. Most sizes are the same on every screen. A few differ, such as `$cx-size-website-section-icon`: `5rem` on large, `4rem` on medium and `3rem` on small screens.

Load the number files with their own namespaces and use them in media queries. The breakpoints are yours to choose:

```scss
@use "@chassis-ui/tokens/dist/web/docs/chassis/number-large" as large;
@use "@chassis-ui/tokens/dist/web/docs/chassis/number-medium" as medium;
@use "@chassis-ui/tokens/dist/web/docs/chassis/number-small" as small;

.section-icon {
  width: large.$cx-size-website-section-icon;
}

@media (max-width: 992px) {
  .section-icon {
    width: medium.$cx-size-website-section-icon;
  }
}

@media (max-width: 768px) {
  .section-icon {
    width: small.$cx-size-website-section-icon;
  }
}
```

Compiled CSS:

```css
.section-icon {
  width: 5rem;
}

@media (max-width: 992px) {
  .section-icon {
    width: 4rem;
  }
}

@media (max-width: 768px) {
  .section-icon {
    width: 3rem;
  }
}
```

## A Token Layer

Collect the modules you use in one partial and forward them, so that components load a single file. Every token file declares `$prefix`, and `main.scss` shares the component colours with the colour files and the sizes with the number files. Forward one file as it is and give the others a prefix:

```scss
// styles/_tokens.scss
@forward "@chassis-ui/tokens/dist/web/docs/chassis/main";
@forward "@chassis-ui/tokens/dist/web/docs/chassis/color-light" as light-*;
@forward "@chassis-ui/tokens/dist/web/docs/chassis/color-dark" as dark-*;
```

```scss
// components/card.scss
@use "../styles/tokens";

.card {
  padding: tokens.$cx-space-context-large;
  border-radius: tokens.$cx-border-radius-context-large;
  background: tokens.$light-cx-color-context-default-bg-main;
}
```

## Bundler Setup

The token files are plain SCSS and need no bundler plugin beyond Sass support. The package paths in the examples resolve through `node_modules`.

### Vite

Vite compiles SCSS once `sass` is installed. Use the tokens in any stylesheet or component style block:

```html
<!-- Card.vue -->
<style lang="scss">
@use "@chassis-ui/tokens/dist/web/docs/chassis/main" as tokens;

.card {
  padding: tokens.$cx-space-context-medium;
}
</style>
```

To make a module available in every stylesheet, add it with `additionalData`. Stylesheets then use `tokens.` without loading the module, and must not load it again under the same namespace:

```javascript
// vite.config.js
import { defineConfig } from 'vite';

export default defineConfig({
  css: {
    preprocessorOptions: {
      scss: {
        additionalData: `@use "@chassis-ui/tokens/dist/web/docs/chassis/main" as tokens;\n`
      }
    }
  }
});
```

### Astro

Astro uses Vite, so the Vite setup applies. With `sass` installed, component styles can use the tokens:

```astro
---
// Card.astro
---

<div class="card">
  <slot />
</div>

<style lang="scss">
  @use "@chassis-ui/tokens/dist/web/docs/chassis/main" as tokens;

  .card {
    padding: tokens.$cx-space-context-medium;
  }
</style>
```

### Next.js

Next.js compiles SCSS and CSS Modules once `sass` is installed. Each module loads the token files it uses:

```scss
// components/Button.module.scss
@use "@chassis-ui/tokens/dist/web/docs/chassis/main" as tokens;
@use "@chassis-ui/tokens/dist/web/docs/chassis/color-light" as color;

.button {
  padding: tokens.$cx-space-button-medium-padding-y tokens.$cx-space-button-medium-padding-x;
  background: color.$cx-color-context-primary-bg-solid;
  color: color.$cx-color-context-primary-fg-solid;
}
```

### Webpack

Use `sass-loader` as usual:

```javascript
// webpack.config.js
module.exports = {
  module: {
    rules: [
      {
        test: /\.scss$/,
        use: ['style-loader', 'css-loader', 'sass-loader']
      }
    ]
  }
};
```

### Other Tools

If a tool does not resolve package paths in Sass, add `node_modules` to the Sass load paths, for example `loadPaths: ['node_modules']` in the Sass options.

## Best Practices

✅ **Prefer context tokens**: Use `color.context.*`, `space.context.*` and `borderRadius.context.*` over primitive and base tokens. Context tokens carry the meaning; base tokens are the raw scale.

✅ **Load with @use and namespaces**: This keeps themes and screen sizes apart and prepares for Dart Sass 3.

✅ **Map tokens in one place**: Turn tokens into your own custom properties or aliases in one partial, and use those in components.

✅ **Change tokens at the source**: Chassis Tokens is meant to be owned and customized. Change values in Tokens Studio and rebuild, instead of editing the files in `dist/`.

✅ **Test both themes**: Check every component in light and dark mode.

❌ **Don't use Chassis CSS values without Chassis CSS**: `var(--…)` values in the default output do nothing unless Chassis CSS defines them.

❌ **Don't mix unit systems**: Stick to one unit system (rem, px, or vw) per project, and avoid mixing token sizes with hard-coded values in another unit.

❌ **Don't hardcode values**: Use tokens instead of magic numbers.

## Troubleshooting

### Undefined Variable

The variable is not declared in the modules you loaded, or it is used without its namespace. Context colours are in the colour files only, so loading `main.scss` is not enough for `$cx-color-context-*`. Check the name in the file in `dist/web/`: names are kebab-case, such as `$cx-typography-font-size-text-xlarge`.

### "Isn't a Valid CSS Value"

A typography map was used as a value. See [Typography](#typography).

### The Dark Theme Shows Light Colours

Both colour files were loaded with `@import`. Each variable is declared with `!default`, so the first file wins. Load them with `@use` and namespaces, as in [Themes](#themes). The same applies to the number files.

### Values Print as var(--…) and Do Nothing

The default output is made for Chassis CSS. Load Chassis CSS, or build the tokens with a preset for other CSS frameworks.

### Deprecation Warning for @import

Dart Sass warns that `@import` will be removed. Load the token files with `@use`.

### Output Built with outputReferences

With the `outputReferences` option, the colour tokens of `main.scss` reference variables of the colour files. Such a `main.scss` cannot be loaded with `@use`, because a module does not see the variables of another module. Load it with `@import` after one colour file:

```scss
// Your build output, for example dist/web/docs/chassis/
@import "path/to/tokens/color-light";
@import "path/to/tokens/main";
```
