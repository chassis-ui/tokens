## Introduction

Color tokens define the colors of text, surfaces, borders, icons, links, shadows, and gradients. A brand sets one base color per palette, and the shades, the context colors, and the component colors are derived from these base colors. The context and the component colors have a value for the light and for the dark theme.

The values on this page are those of the `chassis` brand. Tables with a `Light` and a `Dark` column show the value of a token in both themes.

### Token levels

Color tokens have the three token levels and a fourth group, the primitive colors. The base tokens hold the colors of every theme, and the context tokens select the colors of the current theme. A component color resolves through the three levels:

```text
color.button.default.fg-idle                     component token
  {color.context.default.fg-idle}                context token
    {color.base.context.light.default.fg-idle}   base token of the light theme
      {color.base.context.light.default.fg-main}
        {color.base.primitive.light.neutral.90}
          {color.base.primitive.light.neutral.base}
```

In the dark theme, `color.context.default.fg-idle` references `{color.base.context.dark.default.fg-idle}`, and the rest of the chain follows the dark tokens. The primitive colors select the palette of the current theme in the same way: `color.primitive.neutral.90` references `{color.base.primitive.light.neutral.90}` in the light theme.

The token sets of these groups are in `packages/tokens/source/base/`.

<CxTable>
| Group | Level | Content | Token set |
| --- | --- | --- | --- |
| `color.base.primitive.<theme>.*` | Base | Palettes of the light and the dark theme | `brand-base.json` |
| `color.base.context.<theme>.*` | Base | Context colors of the light and the dark theme | `brand-base.json` |
| `color.base.shadow.<theme>.*` | Base | Shadow colors of the light and the dark theme | `brand-base.json` |
| `color.primitive.*` | Primitive | Palettes of the current theme | `theme-base.json`, `theme-dark.json` |
| `gradient.primitive.*` | Primitive | Gradients of the palettes | `theme-base.json` |
| `color.context.*` | Context | Colors named by role, in eleven contexts | `theme-base.json`, `theme-dark.json` |
| `color.shadow.*` | Context | Shadow colors of the current theme | `theme-base.json`, `theme-dark.json` |
| `color.utility.*` | Context | Colors that the build does not write | `theme-base.json`, `theme-dark.json` |
| `color.<component>.*` | Component | Colors of the parts of a component | `app-base.json`, `app-demo.json` |
</CxTable>

`theme-base.json` references the light base tokens, and `theme-dark.json` replaces these references with the dark ones. See the [Tokens Studio]([[docsref:/getting-started/tokens-studio]]) guide for the token sets and the themes that select them.

## Base tokens

Base tokens hold the colors of both themes at once, under `color.base.primitive`, `color.base.context`, and `color.base.shadow`, each with a `light` and a `dark` group. They are the source of the other color tokens and do not follow the theme of an app.

### Palettes

A palette is a group of colors that are derived from one base color. There are eleven palettes: `black`, `white`, `primary`, `secondary`, `neutral`, `danger`, `success`, `warning`, `info`, `brand`, and `accent`. The token set of a brand, such as `packages/tokens/source/brand-chassis/brand-base.json`, sets the `base` token of a palette.

<CxTable>
| Token | Value |
| --- | --- |
| `color.base.primitive.light.black.base` | `#000000` |
| `color.base.primitive.light.white.base` | `#ffffff` |
| `color.base.primitive.light.primary.base` | `#00A4CC` |
| `color.base.primitive.light.secondary.base` | `#F55200` |
| `color.base.primitive.light.neutral.base` | `#6F8085` |
| `color.base.primitive.light.danger.base` | `#F52314` |
| `color.base.primitive.light.success.base` | `#10C263` |
| `color.base.primitive.light.warning.base` | `#F5A300` |
| `color.base.primitive.light.info.base` | `#1414F5` |
| `color.base.primitive.light.brand.base` | `#00A4CC` |
| `color.base.primitive.light.accent.base` | `#F55200` |
</CxTable>

In the `chassis` brand, `brand` and `accent` have the base colors of `primary` and `secondary`. Each `color.base.primitive.dark.<palette>.base` references the base color of the light theme, so both themes have the same palettes.

Every palette has two more tokens next to `base`. `contrast` is the color of text and icons on the base color: `#ffffff`, except for `warning` and `white`, whose contrast color is `#000000`. `transparent` is the base color with `opacity.level.zero`.

### Shades

Shades are lighter and darker steps of the base color, named from `05` for the lightest to `95` for the darkest. Every palette except `black` and `white` has them. A shade references the base color with a color modifier of Tokens Studio: `lighten` moves the color toward white and `darken` toward black in the sRGB color space, by the share that a `modify.*` token holds.

## Primitive colors

Primitive colors are the palettes of the current theme. Each `color.primitive.<palette>.<name>` references the base token of the same name: `color.base.primitive.light.*` in the light theme and `color.base.primitive.dark.*` in the dark theme.

<CxTable>
| Token | Value | Light reference | Dark reference |
| --- | --- | --- | --- |
| `color.primitive.primary.50` | `#00A4CC` | `{color.base.primitive.light.primary.50}` | `{color.base.primitive.dark.primary.50}` |
| `color.primitive.primary.base` | `#00A4CC` | `{color.base.primitive.light.primary.base}` | `{color.base.primitive.dark.primary.base}` |
| `color.primitive.primary.contrast` | `#ffffff` | `{color.base.primitive.light.primary.contrast}` | `{color.base.primitive.dark.primary.contrast}` |
| `color.primitive.primary.transparent` | `rgba(0, 164, 204, 0)` | `{color.base.primitive.light.primary.transparent}` | `{color.base.primitive.dark.primary.transparent}` |
| `color.primitive.primary.t-5050` | `rgba(0, 164, 204, 0.5)` | `{color.base.primitive.light.primary.t-5050}` | `{color.base.primitive.dark.primary.t-5050}` |
</CxTable>

The names after the palette are those of the base tokens: `base`, `contrast`, `transparent`, the shades, and the transparency colors. In the `chassis` brand the light and the dark palettes are equal, so the primitive colors have the same value in both themes.

### Gradients

Gradient tokens are linear gradients from the `transparent` to the `base` color of a palette, in eight directions. `gradient.primitive.<palette>.l-50-<angle>` names the angle in three digits, from `000` to `315` in steps of 45 degrees. The gradients of `black` and `white` leave out the shade: `gradient.primitive.black.l-090`.

## Context tokens

Context tokens name a color by its role, such as `fg-main` for text and `bg-main` for the surface under it. There are eleven contexts, and every context has the same roles, so a component changes its context without changing the roles it uses.

<CxTable>
| Context | Colors |
| --- | --- |
| `default` | Dark text on a light surface in the light theme, light text on a dark surface in the dark theme |
| `alternate` | Light text on a dark surface in both themes |
| `primary`, `secondary`, `neutral`, `danger`, `success`, `warning`, `info` | Shades and transparency colors of the palette with the name of the context |
| `black`, `white` | Base color and transparency colors of the `black` and the `white` palette |
</CxTable>

## Component tokens

Component tokens assign a context color to a part of a component. Every component color references a token of `color.context.*`, so it follows the theme. The `Reference` column shows this context token.

## Usage

Choose the token of the most specific level that fits, because only the context and the component tokens follow the theme.

- Use a component token for a part of its component: `color.table.bg-alt` for the alternating rows of a table.
- Use a context token for everything that has no component token. Choose the context by meaning (`danger` for an error) and the role by function (`fg-main` for text, `border-subtle` for a divider).
- Use a primitive color only when no role has the shade, as the gradients do with `color.primitive.primary.base`.
- Do not use `color.base.*` in an app. A base token such as `color.base.context.light.default.fg-main` keeps the value of the light theme in the dark theme.

Take the foreground and the background from the same context and from roles that belong together. `fg-main`, `fg-subtle`, and `fg-slight` go on `bg-main`, `bg-even`, and `bg-evident`. `fg-solid`, `fg-inverse`, `fg-highlight`, and `fg-active` go on the `bg` role of the same name, and each `fg` state role goes on the `bg` role of the same state.

## Accessibility

The contrast between a foreground and a background role depends on the pair. WCAG 2 asks for a contrast ratio of 4.5:1 for text, and of 3:1 for large text and for the parts of a control. The ratios of `color.context.default` in the `chassis` brand are computed from the values of the [roles](#roles), with translucent colors placed on their background.

<CxTable>
| Foreground | Background | Light | Dark |
| --- | --- | --- | --- |
| `fg-main` | `bg-main` | 17.5:1 | 15.7:1 |
| `fg-main` | `bg-even` | 16.2:1 | 14.8:1 |
| `fg-main` | `bg-evident` | 14.8:1 | 12.9:1 |
| `fg-subtle` | `bg-main` | 3.4:1 | 4.7:1 |
| `fg-slight` | `bg-main` | 1.7:1 | 2.1:1 |
| `fg-solid` | `bg-solid` | 17.7:1 | 15.3:1 |
| `fg-inverse` | `bg-inverse` | 14.8:1 | 14.8:1 |

In `color.context.default`, `fg-subtle`, `fg-slight`, and `fg-disabled` are `fg-main` with a lower alpha value, so their contrast is lower than that of `fg-main` on every background. The ratios depend on the base colors of the brand and on the context, so measure the pairs of another brand or context before relying on them.

## Platform output

Colors print as hex or `rgba()` values on the web, as `UIColor` on iOS, and as `<color>` resources in ARGB hex on Android.

<CxTable>
| Platform | Name | Value |
| --- | --- | --- |
| Web | `$cx-color-context-default-fg-main` | `#161a1b` |
| iOS | `ColorContextDefaultFgMain` | `UIColor(red: 0.086, green: 0.102, blue: 0.106, alpha: 1)` |
| Android | `@color/color_context_default_fg_main` | `#ff161a1b` |
</CxTable>

The build writes the primitive colors, the context colors, and the gradients into the color file of each theme, such as `color-light.scss` and `color-dark.scss`. The component and the shadow colors are in these files too. The main file has the base colors, and the component and the shadow colors with the values of the light theme.

On the web, a color with an alpha value prints as `rgba()`. With the `web` platform, a color that references a context or a primitive color prints the custom property of Chassis CSS instead of its value, so every component color is a `var(--…)` reference. The build writes these lines into `color-light.scss`:

```scss
$cx-color-context-default-fg-main: #161a1b !default;
$cx-color-context-default-fg-subtle: rgba(22, 26, 27, 0.5) !default;
$cx-color-button-default-fg-idle: var(--default-fg-idle) !default;
```

On iOS, the channels are numbers from 0 to 1 with three decimals. The build writes these constants into `ColorLight.swift`:

```swift
    public static let ColorContextDefaultFgMain = UIColor(red: 0.086, green: 0.102, blue: 0.106, alpha: 1)
    public static let ColorContextDefaultFgSubtle = UIColor(red: 0.086, green: 0.102, blue: 0.106, alpha: 0.5)
```

`Color.swift` has the same names with colors that follow the appearance of the device: a constant whose light and dark values differ is a dynamic `UIColor` that holds both.

On Android, the alpha value comes first in the hex number: `#80161a1b` is `#161a1b` with an alpha value of 0.5. The build writes these resources into `color_light.xml`:

```xml
  <color name="color_context_default_fg_main">#ff161a1b</color>
  <color name="color_context_default_fg_subtle">#80161a1b</color>
```

A gradient prints as a `linear-gradient()` value on the web. On iOS and Android the build splits it into an angle and, for each stop, a color and a position: `GradientPrimitivePrimaryL50090Angle`, `GradientPrimitivePrimaryL50090Stop1Color`, and `GradientPrimitivePrimaryL50090Stop1Position` on iOS, `gradient_primitive_primary_l_50_090_angle`, `gradient_primitive_primary_l_50_090_stop_1_color`, and `gradient_primitive_primary_l_50_090_stop_1_position` on Android.

See the [web]([[docsref:/use-in-project/web-applications]]), [iOS]([[docsref:/use-in-project/ios-applications]]), and [Android]([[docsref:/use-in-project/android-applications]]) docs for the files that hold these names.
