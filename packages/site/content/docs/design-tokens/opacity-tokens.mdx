## Introduction

Opacity tokens hold alpha values from `0` to `1`. The color tokens reference them to build the transparent colors of the palette and the subtle colors of text, borders, and icons. The values are the same in every brand, app, theme, and screen.

### Token levels

Opacity tokens have two levels, and neither references the other. Base tokens (`opacity.level.*`) hold a scale of levels, and context tokens (`opacity.context.*`) hold a value named by the role of a color. A context token holds a number of its own: `opacity.context.fg-subtle` is `0.5`, not `{opacity.level.50}`, and `opacity.context.fg-slight` is `0.25`, a value that the scale does not have. The category has no component tokens.

Both levels are in `packages/tokens/source/base/metric-base.json`.

## Base tokens

Base tokens hold the opacity scale: `zero`, `solid`, and the levels between them, named by their percentage. The transparent colors of the palette reference the levels from `05` to `95`; see [Usage](#usage).

## Context tokens

Context tokens hold the alpha of a color role, and carry the name of that role. The colors of the same name in `color.base.context.*` reference them, in the color groups of both themes.

<CxTable>
| Token | Value | Purpose |
| --- | --- | --- |
| `opacity.context.fg-subtle` | `0.5` | Alpha of the `fg-subtle` colors and of the shadow color of `bg-blur.*` |
| `opacity.context.fg-slight` | `0.25` | Alpha of the `fg-slight` and `fg-disabled` colors |
| `opacity.context.border-main` | `0.4` | Not referenced by a token |
| `opacity.context.border-subtle` | `0.15` | Alpha of the `border-subtle` colors |
| `opacity.context.icon-subtle` | `0.4` | Alpha of the `icon-subtle` colors |
| `opacity.context.icon-slight` | `0.2` | Alpha of the `icon-slight` colors |
| `opacity.context.cue-slight` | `0.2` | Alpha of the `cue-slight` colors |
| `opacity.context.dim-main` | `0.7` | Not referenced by a token |
| `opacity.context.dim-subtle` | `0.3` | Not referenced by a token |
| `opacity.context.dim-slight` | `0.05` | Not referenced by a token |
| `opacity.context.transparent-color` | `0` | Not referenced by a token |
</CxTable>

The colors named `border-main`, `dim-main`, `dim-subtle`, `dim-slight`, and `transparent-color` get their value another way. `color.base.context.light.default.dim-main` references the palette color `{color.base.primitive.light.black.t-70}`, and `color.base.context.light.default.transparent-color` references `{opacity.level.zero}`. A change to `opacity.context.dim-main` does not change a color.

## Usage

Color tokens reference the opacity tokens, so an app that needs a transparent color uses the color token. The [color tokens]([[docsref:/design-tokens/color-tokens]]) page lists these colors.

### Opacity in colors

A transparent color holds `rgba()` with two references: a color and an opacity. In `packages/tokens/source/base/brand-base.json`, the black of the palette at 30 percent is defined like this:

```json
"t-30": {
  "$type": "color",
  "$value": "rgba({color.base.primitive.light.black.base}, {opacity.level.30})"
}
```

The build resolves the two references and writes the color with its alpha, as the values of these three colors show.

<CxTable>
| Token | Reference | Value |
| --- | --- | --- |
| `color.base.primitive.light.black.t-30` | `rgba({color.base.primitive.light.black.base}, {opacity.level.30})` | `rgba(0, 0, 0, 0.3)` |
| `color.base.primitive.light.primary.t-5030` | `rgba({color.base.primitive.light.primary.50}, {opacity.level.30})` | `rgba(0, 164, 204, 0.3)` |
| `color.base.context.light.default.fg-subtle` | `rgba({color.base.context.light.default.fg-main}, {opacity.context.fg-subtle})` | `rgba(22, 26, 27, 0.5)` |
</CxTable>

Three groups of colors follow this pattern:

- **Black and white**: `t-<level>` applies `opacity.level.<level>` to the `base` color, from `t-05` to `t-95`.
- **The other colors of the palette**: `t-50<level>` applies `opacity.level.<level>` to step `50` of the color, from `t-5005` to `t-5095`.
- **Context colors**: a subtle or slight color applies an `opacity.context.*` token to a solid color of its group, such as `fg-main`, `icon-main`, or `cue-main`. The `fg-hover` and `fg-press` colors apply `opacity.level.90` in the same way.

`opacity.level.zero` is the alpha of the `transparent` color of each palette color and of the `transparent-color` of each color group. No token references `opacity.level.solid`.

### Choosing a token

The level to change depends on how far the change must reach. A change to `opacity.level.30` changes every `t-30` and `t-5030` color of both themes, and a change to `opacity.context.fg-subtle` changes the `fg-subtle` colors that reference it.

- **A transparent color in an app**: use the color token, such as `color.context.default.fg-subtle`, and not a color combined with an opacity token.
- **A new transparent color token**: reference an `opacity.context.*` token when its role has one, and a level of `opacity.level.*` otherwise.
- **The opacity of an element**: use a level of `opacity.level.*`.

## Platform output

An opacity prints as a number without a unit on the web, as a `CGFloat` on iOS, and as a float item on Android.

<CxTable>
| Platform | Name | Value |
| --- | --- | --- |
| Web | `$cx-opacity-context-fg-subtle` | `0.5` |
| iOS | `OpacityContextFgSubtle` | `CGFloat(0.5)` |
| Android | `@dimen/opacity_context_fg_subtle` | `0.5` |
</CxTable>

On the `web` platform, an opacity token that references another opacity token prints a custom property of Chassis CSS, `var(--opacity-<name>)`. No opacity token holds a reference, so every one prints its number.

On Android, the build writes an `<item>` of the type `dimen` with the format `float` instead of a `<dimen>` element, and the reference of the item starts with `@dimen/`, as for a size. The build writes this line:

```xml
  <item name="opacity_context_fg_subtle" type="dimen" format="float">0.5</item>
```

A color that references an opacity token prints with its alpha, and not with a reference to the opacity. `color.context.default.fg-subtle` prints as `rgba(22, 26, 27, 0.5)` on the web, as `UIColor(red: 0.086, green: 0.102, blue: 0.106, alpha: 0.5)` on iOS, and as `#80161a1b` on Android, where the first two digits are the alpha.

See the [web]([[docsref:/use-in-project/web-applications]]), [iOS]([[docsref:/use-in-project/ios-applications]]), and [Android]([[docsref:/use-in-project/android-applications]]) docs for the files that hold these names.
