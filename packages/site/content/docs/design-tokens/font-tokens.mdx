## Introduction

Font tokens are composite tokens: each holds a whole text style, where a [typography token]([[docsref:/design-tokens/typography-tokens]]) holds one property. A font token has the type `typography`, and its value is an object with a font family, a font weight, a font size, a line height, a letter spacing, and a paragraph spacing. No font token names a text case or a text decoration.

Each property references a typography token, as `font.ui.medium.strong` shows in `source/base/app-base.json`:

```json
{
  "font": {
    "ui": {
      "medium": {
        "strong": {
          "$type": "typography",
          "$value": {
            "fontFamily": "{typography.fontFamily.ui}",
            "fontWeight": "{typography.fontWeight.ui.strong}",
            "lineHeight": "{typography.lineHeight.ui.medium}",
            "fontSize": "{typography.fontSize.ui.medium}",
            "letterSpacing": "{typography.letterSpacing.ui.strong}",
            "paragraphSpacing": "{typography.paragraphSpacing.base.zero}"
          }
        }
      }
    }
  }
}
```

The build adds one more property, the font style, which it takes from the font weight: `normal`, or the style that the weight names, such as `italic`.

Font tokens hold references, so their values follow the typography tokens. A brand changes the text styles by overriding the font families and the font weights, or the typography tokens of one text role or role group, and no font token has to change. Where the token system has the optional `screen` group, `font.website.*` differs per screen, because its font sizes do.

### Token levels

Font tokens have three levels. Base tokens combine the typography tokens of one family, one size, and one weight. Context tokens combine the typography tokens of one text role. Component tokens hold a reference to a base token.

```text
typography.fontFamily.ui
typography.fontWeight.ui.strong
typography.fontSize.ui.medium
typography.lineHeight.ui.medium
  font.ui.medium.strong               references them
    font.button.medium                {font.ui.medium.strong}
```

## Base tokens

Base tokens are named `font.<family>.<size>.<weight>`. Each combines the family, the weight, the font size, and the line height that the typography tokens hold under the same names: `font.prose.large.mass` references `{typography.fontFamily.prose}`, `{typography.fontWeight.prose.mass}`, `{typography.fontSize.prose.large}`, and `{typography.lineHeight.prose.large}`.

<CxTable>
| Token | Sizes | Weights |
| --- | --- | --- |
| `font.ui.<size>.<weight>` | `5xlarge`, `4xlarge`, `3xlarge`, `2xlarge`, `xlarge`, `large`, `medium`, `small`, `xsmall`, `2xsmall` | `normal`, `strong`, `mass`, `elegant` |
| `font.prose.<size>.<weight>` | `5xlarge`, `4xlarge`, `3xlarge`, `2xlarge`, `xlarge`, `large`, `medium`, `small`, `xsmall`, `2xsmall` | `normal`, `strong`, `mass`, `elegant` |
| `font.code.<size>.<weight>` | `large`, `medium`, `small` | `normal`, `strong` |
</CxTable>

A base token of the `ui` or `prose` family takes its letter spacing from its weight, such as `{typography.letterSpacing.prose.mass}`, and `font.code.*` references `{typography.letterSpacing.base.zero}`. Every base token references `{typography.paragraphSpacing.base.zero}`.

The `display` family has no base tokens, because it has no scale. Text is set in it through a [context token](#context-tokens) whose role group a brand points at the display family.

## Context tokens

Context tokens name a text style by its role in the content. Each takes its properties from the typography tokens of its role, in the `context` group of `source/base/brand-base.json`, which a brand can override. The font size, the line height, and the letter spacing belong to the role, such as `{typography.fontSize.context.h1}` and `{typography.letterSpacing.context.h1}`. The family and the weight belong to the role group, which the roles of the group share: `font.context.h1` to `font.context.h6` reference `{typography.fontFamily.context.heading}` and `{typography.fontWeight.context.heading}`. ## Usage

Choose the level that names the text:

- Use a component token for the part of a component that it names, such as `font.button.medium` for the label of a medium button.
- Use a context token for content with a role: `font.context.h2` for a heading, `font.context.body.medium` for running text, `font.context.label.small` for the label of a control.
- Use a base token where no context or component token fits: `font.ui.*` in an interface, `font.prose.*` in reading content.

The display family has no base tokens, so a context token is the way to set a text in it. Point the family and the weight of the role group of that token at the display family in the token set of the brand, as [Usage]([[docsref:/design-tokens/typography-tokens#usage]]) of the typography tokens shows. A font token takes its weight from the family it takes its family from, which `pnpm tokens:lint:source` checks.

Give a new component token a reference to a base token of the `ui` family, as the existing component tokens have. The token then follows the typography scales and the fonts of each brand.

A font token holds no color. Set the color of a text with a [color token]([[docsref:/design-tokens/color-tokens]]).

## Platform output

A font token prints as one Sass map on the web, and as one constant or resource per property on iOS and Android. The table shows the font size of `font.context.jumbo` on iOS and Android.

<CxTable>
| Platform | Name | Format |
| --- | --- | --- |
| Web | `$cx-font-context-jumbo` | A Sass map with one key per property |
| iOS | `FontContextJumboFontSize` | A `CGFloat` in points |
| Android | `@dimen/font_context_jumbo_font_size` | A `<dimen>` in `sp` |
</CxTable>

The values in the examples of this section are those of the `chassis` brand in the current version, and they differ in other brands.

The build writes the map of the web to `main.scss`, on one line. The keys are CSS properties: the paragraph spacing is `margin-bottom`, and the text case is `text-transform`. Every map has the keys `text-transform` and `text-decoration`, and a font token that names no text case or text decoration has `none` for it, on every platform.

```scss
$cx-font-context-jumbo: ("font-family": var(--font-family-display), "font-weight": var(--font-weight-display-mass), "font-size": 6rem, "line-height": var(--line-height-jumbo), "font-style": normal, "letter-spacing": -0.15625rem, "margin-bottom": 0rem, "text-transform": none, "text-decoration": none) !default;
```

The `web` platform names the custom properties of Chassis CSS for the family, the weight, the font size, and the line height that a font token references, so its maps work with Chassis CSS only:

- A base token names the properties of its family and step, such as `var(--font-size-ui-md)`, and a component token names those of the base token it references.
- A context token names the family and the weight that its role group points to in the brand: `var(--font-family-display)` in the example, where the role group `jumbo` points at the display family, and the property of another family in a brand that points the group at it.
- A context token names the font size and the line height of its role, without the group and with the short name of the size: `var(--font-size-h1)`, `var(--line-height-title-lg)`.
- A role whose size references another group, as `jumbo` and `hero` reference `size.unit.*`, prints the size, and a role group that holds a value of its own prints the value.

`$cx-font-context-h1` shows the custom properties of a role:

```scss
$cx-font-context-h1: ("font-family": var(--font-family-display), "font-weight": var(--font-weight-display-mass), "font-size": var(--font-size-h1), "line-height": var(--line-height-h1), "font-style": normal, "letter-spacing": 0rem, "margin-bottom": 0rem, "text-transform": none, "text-decoration": none) !default;
```

The presets `web-scss`, `web-px`, and `web-vw` print the values; see the [Style Dictionary]([[docsref:/getting-started/style-dictionary]]) page.

iOS and Android name each constant or resource after the token and the property. The format of a property is the format of its [typography token]([[docsref:/design-tokens/typography-tokens]]), except for the line height and the letter spacing.

<CxTable>
| Property | iOS | Android |
| --- | --- | --- |
| Font family | `FontContextJumboFontFamily` | `@string/font_context_jumbo_font_family` |
| Font weight | `FontContextJumboFontWeight` | `@integer/font_context_jumbo_font_weight` |
| Line height | `FontContextJumboLineHeight` | `@dimen/font_context_jumbo_line_height` |
| Font size | `FontContextJumboFontSize` | `@dimen/font_context_jumbo_font_size` |
| Letter spacing | `FontContextJumboLetterSpacing` | `@dimen/font_context_jumbo_letter_spacing` |
| Paragraph spacing | `FontContextJumboParagraphSpacing` | `@dimen/font_context_jumbo_paragraph_spacing` |
| Text case | `FontContextJumboTextCase` | `@string/font_context_jumbo_text_case` |
| Text decoration | `FontContextJumboTextDecoration` | `@string/font_context_jumbo_text_decoration` |

The build writes the sizes of a font token to the number file of each screen, and the other properties to the string file. The main file holds all of them. On iOS, `NumberLarge.swift` has these lines:

```swift
    public static let FontContextJumboLineHeight = CGFloat(120)
    public static let FontContextJumboFontSize = CGFloat(96)
    public static let FontContextJumboLetterSpacing = CGFloat(-2.5)
    public static let FontContextJumboParagraphSpacing = CGFloat(0)
```

On Android, `number_large.xml` has the same properties:

```xml
  <dimen name="font_context_jumbo_line_height">120sp</dimen>
  <dimen name="font_context_jumbo_font_size">96sp</dimen>
  <item name="font_context_jumbo_letter_spacing" type="dimen" format="float">-0.026</item>
  <dimen name="font_context_jumbo_paragraph_spacing">0sp</dimen>
```

The line height and the letter spacing print by rules of their own inside a font token:

- A line height that is a percentage, as in `font.website.*`, prints in `em` on the web. iOS and Android print a size: that percentage of the font size of the same token.
- The letter spacing is in design pixels, the same at every font size, as in Figma. The web prints it in `rem` and iOS in points. Android prints it in ems of the font size of the same token, which `android:letterSpacing` takes: the `-2.5` of the iOS lines at a font size of `96` is the `-0.026` of the Android lines.

See the [web]([[docsref:/use-in-project/web-applications]]), [iOS]([[docsref:/use-in-project/ios-applications]]), and [Android]([[docsref:/use-in-project/android-applications]]) docs for the files that hold these names.
