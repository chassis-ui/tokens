## Introduction

Typography tokens hold the single properties of a text style. Each property has a group under `typography.*`: `fontFamily`, `fontWeight`, `fontSize`, `lineHeight`, `letterSpacing`, `paragraphSpacing`, `textCase`, and `textDecoration`. The [font tokens]([[docsref:/design-tokens/font-tokens]]) combine these properties into text styles.

The values on this page are those of the `chassis` brand and the `large` screen. Typography tokens have the same values in the `light` and the `dark` theme, and in the `docs` and the `demo` app.

### Token levels

Typography tokens are base tokens: each holds a raw value, and a few reference another typography token or a size. The category has no context or component tokens of its own. The next level is the `font.*` tokens, which reference the typography tokens property by property.

Brands and screens change typography tokens by overriding them in their own token sets.

<CxTable>
| Tokens | Token set |
| --- | --- |
| `typography.fontFamily.*`, `typography.fontWeight.*` | `packages/tokens/source/base/brand-base.json`, overridden by `brand-base.json` of `source/brand-chassis/` and `source/brand-sinefil/` |
| `typography.fontSize.*`, `typography.lineHeight.*` | `packages/tokens/source/base/brand-base.json` |
| `typography.fontSize.website.*` | `screen-large.json`, `screen-medium.json`, and `screen-small.json` of `packages/tokens/source/screen-website/` |
| `typography.letterSpacing.*`, `typography.paragraphSpacing.*`, `typography.textCase.*`, `typography.textDecoration.*` | `packages/tokens/source/base/app-base.json` |
</CxTable>

## Font families

Font family tokens hold a font stack: the font of the brand, followed by its fallbacks. The font tokens of each group take their family from the token of the same name.

<CxTable>
| Token | Value | Purpose |
| --- | --- | --- |
| `typography.fontFamily.text` | `Inter, system-ui, -apple-system, Helvetica, Arial, sans-serif` | Family of `font.text.*`, `font.website.*`, and `font.context.*` except `font.context.code.*` |
| `typography.fontFamily.display` | `'Archivo Narrow', Georgia, 'Times New Roman', Times, serif` | Family of `font.display.*` |
| `typography.fontFamily.html` | `Inter, system-ui, -apple-system, Helvetica, Arial, sans-serif` | Family of `font.html.*` |
| `typography.fontFamily.code` | `Fira Code, Menlo, Monaco, Consolas, 'Courier New', monospace` | Family of `font.code.*`, `font.context.code.*`, and `font.html.code` |
| `typography.fontFamily.icon` | `Chassis-Icons` | Family of the icon font |
</CxTable>

`typography.fontFamily.html` is a reference. It holds `{typography.fontFamily.text}` in the `chassis` brand and `{typography.fontFamily.display}` in the `sinefil` brand.

The `sinefil` brand overrides every family except `typography.fontFamily.icon`.

<CxTable>
| Token | `chassis` | `sinefil` |
| --- | --- | --- |
| `typography.fontFamily.text` | `Inter, system-ui, -apple-system, Helvetica, Arial, sans-serif` | `'DM Sans', Inter, system-ui, sans-serif` |
| `typography.fontFamily.display` | `'Archivo Narrow', Georgia, 'Times New Roman', Times, serif` | `'Source Serif 4','Source Serif Pro', ui-serif, serif` |
| `typography.fontFamily.html` | `Inter, system-ui, -apple-system, Helvetica, Arial, sans-serif` | `'Source Serif 4','Source Serif Pro', ui-serif, serif` |
| `typography.fontFamily.code` | `Fira Code, Menlo, Monaco, Consolas, 'Courier New', monospace` | `'IBM Plex Mono', 'Courier New', Courier, monospace` |
</CxTable>

## Font weights

Font weight tokens name the weights of a family by role: `normal`, `strong`, `mass`, and `elegant` for the text and the display family, `normal` and `strong` for the code family. The value is the style name of the font in Figma, such as `Semi Bold` or `Light Italic`.

The build splits every font weight token into two tokens, `<token>.weight` and `<token>.style`. `typography.fontWeight.html.blockquote` holds `Light Italic`, so the build writes `typography.fontWeight.html.blockquote.weight` with `Light` and `typography.fontWeight.html.blockquote.style` with `italic`. A value that names no style gets the style `normal`. The Weight and Style columns show what the build prints for the two tokens.

<CxTable>
| Token | Value | Weight | Style |
| --- | --- | --- | --- |
| `typography.fontWeight.text.normal` | `Regular` | `400` | `normal` |
| `typography.fontWeight.text.strong` | `Semi Bold` | `600` | `normal` |
| `typography.fontWeight.text.mass` | `Bold` | `700` | `normal` |
| `typography.fontWeight.text.elegant` | `Light` | `300` | `normal` |
| `typography.fontWeight.display.normal` | `Medium` | `500` | `normal` |
| `typography.fontWeight.display.strong` | `SemiBold` | `600` | `normal` |
| `typography.fontWeight.display.mass` | `Bold` | `700` | `normal` |
| `typography.fontWeight.display.elegant` | `Regular` | `400` | `normal` |
| `typography.fontWeight.code.normal` | `Regular` | `400` | `normal` |
| `typography.fontWeight.code.strong` | `Bold` | `700` | `normal` |
</CxTable>

The source spells one weight two ways: `Semi Bold` for Inter and `SemiBold` for the other fonts, because each font has its own style name in Figma. The build prints `600` for both.

The `sinefil` brand holds `Regular` in `typography.fontWeight.display.normal`, `Light` in `typography.fontWeight.display.elegant`, and `SemiBold` in `typography.fontWeight.text.strong`. The other weights of the text, display, and code families are equal in both brands.

The weights of the HTML elements reference the weights of the text family, so they follow the brand. `typography.fontWeight.html.blockquote` is the only one with a value of its own.

<CxTable>
| Token | Value | Reference |
| --- | --- | --- |
| `typography.fontWeight.html.code` | `Regular` | `{typography.fontWeight.text.normal}` |
| `typography.fontWeight.html.blockquote` | `Light Italic` | |
| `typography.fontWeight.html.body` | `Regular` | `{typography.fontWeight.text.normal}` |
| `typography.fontWeight.html.paragraph` | `Regular` | `{typography.fontWeight.text.normal}` |
| `typography.fontWeight.html.heading` | `Bold` | `{typography.fontWeight.text.mass}` |
| `typography.fontWeight.html.cite` | `Semi Bold` | `{typography.fontWeight.text.strong}` |
| `typography.fontWeight.html.list` | `Regular` | `{typography.fontWeight.text.normal}` |
| `typography.fontWeight.html.bold` | `Bold` | `{typography.fontWeight.text.mass}` |
</CxTable>

## Letter spacing

The letter spacing scale has one step, which every font token without a letter spacing of its own references. The font tokens that tighten their letters reference a negative size instead, such as `{size.unit.nd05}`.

<CxTable>
| Token | Value | Reference |
| --- | --- | --- |
| `typography.letterSpacing.base.zero` | `0px` | `{size.unit.0}` |
</CxTable>

## Paragraph spacing

Paragraph spacing tokens hold the space after a paragraph. Most font tokens reference `typography.paragraphSpacing.base.zero`. The other steps belong to `font.context.heading`, to the context fonts for titles, body text, and highlights, and to `font.html.paragraph`.

<CxTable>
| Token | Value | Purpose |
| --- | --- | --- |
| `typography.paragraphSpacing.base.zero` | `0px` | Every other font token |
| `typography.paragraphSpacing.base.small` | `8px` | The `small` step of `font.context.title.*`, `font.context.body.*`, and `font.context.highlight.*` |
| `typography.paragraphSpacing.base.medium` | `16px` | The `medium` step of the same groups, and `font.html.paragraph` |
| `typography.paragraphSpacing.base.large` | `24px` | The `large` step of the same groups, and `font.context.heading` |
</CxTable>

## Text case and decoration

Text case and text decoration tokens hold keywords, not sizes. Every font token references `typography.textCase.base.none`, and no font token references the other three text case tokens.

<CxTable>
| Token | Value |
| --- | --- |
| `typography.textCase.base.none` | `none` |
| `typography.textCase.base.lowercase` | `lowercase` |
| `typography.textCase.base.uppercase` | `uppercase` |
| `typography.textCase.base.capitalize` | `capitalize` |
</CxTable>

Two groups of font tokens have a text decoration: links are underlined, and expired text is struck through.

<CxTable>
| Token | Value | Purpose |
| --- | --- | --- |
| `typography.textDecoration.base.none` | `none` | Every other font token |
| `typography.textDecoration.base.underline` | `underline` | `font.context.link.*` |

</CxTable>

## Usage

Set text with a [font token]([[docsref:/design-tokens/font-tokens]]), which holds every property of a text style. Use a typography token where one property is needed on its own: `typography.fontFamily.text` for the font stack of a page, `typography.fontWeight.text.strong` for emphasis inside a text.

Take the font size and the line height from the same step. `typography.lineHeight.text.large` is made for `typography.fontSize.text.large`, and the web output of a line height is relative to the font size of its step.

Give a brand its own fonts by overriding `typography.fontFamily.*` and `typography.fontWeight.*` in the token set of the brand. Every font token follows, because the font tokens hold references. The token set of the `sinefil` brand, `packages/tokens/source/brand-sinefil/brand-base.json`, starts its typography group this way:

```json
  "typography": {
    "fontFamily": {
      "text": {
        "$type": "fontFamilies",
        "$value": "'DM Sans', Inter, system-ui, sans-serif"
      },
      "display": {
        "$type": "fontFamilies",
        "$value": "'Source Serif 4','Source Serif Pro', ui-serif, serif"
      },
      "html": {
        "$type": "fontFamilies",
        "$value": "{typography.fontFamily.display}"
      },
```

Write a font weight as the font names it in Figma, and keep that spelling: `Semi Bold` and `SemiBold` are both correct, each for its font. `pnpm tokens:lint:source` reports a weight that the build does not know.

## Platform output

Font sizes and paragraph spacing print in `rem` on the web, in points on iOS, and in `sp` on Android. Line heights print in `em` on the web, and as a size on iOS and Android.

<CxTable>
| Platform | Name | Value |
| --- | --- | --- |
| Web | `$cx-typography-line-height-text-medium` | `1.5em` |
| iOS | `TypographyLineHeightTextMedium` | `CGFloat(24)` |
| Android | `@dimen/typography_line_height_text_medium` | `24sp` |
</CxTable>

The other properties follow rules of their own. The table shows one token of each property.

<CxTable>
| Token | Web | iOS | Android |
| --- | --- | --- | --- |
| `typography.fontFamily.display` | `'Archivo Narrow', Georgia, 'Times New Roman', Times, serif` | `"Archivo Narrow"` | `Archivo Narrow` |
| `typography.fontWeight.text.strong.weight` | `600` | `UIFont.Weight.semibold` | `600` |
| `typography.fontWeight.text.strong.style` | `normal` | `"normal"` | `normal` |
| `typography.fontSize.text.medium` | `1rem` | `CGFloat(16)` | `16sp` |
| `typography.letterSpacing.base.zero` | `0em` | `CGFloat(0)` | `0` |
| `typography.paragraphSpacing.base.medium` | `1rem` | `CGFloat(16)` | `16sp` |
| `typography.textCase.base.uppercase` | `uppercase` | `"uppercase"` | `uppercase` |
</CxTable>

The platforms differ in four properties:

- A font family prints as the whole font stack on the web, and as the first family of the stack on iOS and Android.
- A font weight prints as a number on the web, as a case of `UIFont.Weight` on iOS, and as an `<integer>` resource on Android. Its style prints as a string.
- A line height on the web is divided by the font size of the same step, so `24px` at `16px` prints `1.5em`.
- The letter spacing scale prints in `em` on the web, which is the pixels divided by 16, in points on iOS, and as the number of pixels on Android, in an `<item>` of the type `dimen` with the format `float`.

The web writes the families, weights, text cases, and text decorations to `string.scss`, and the sizes, line heights, and spacings to each `number-<screen>.scss`; `main.scss` holds all of them. iOS and Android split the tokens the same way between their string and number files.

See the [web]([[docsref:/use-in-project/web-applications]]), [iOS]([[docsref:/use-in-project/ios-applications]]), and [Android]([[docsref:/use-in-project/android-applications]]) docs for the files that hold these names.
