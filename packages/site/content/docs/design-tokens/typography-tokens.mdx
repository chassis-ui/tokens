## Introduction

Typography tokens hold the single properties of a text style. Each property has a group under `typography.*`: `fontFamily`, `fontWeight`, `fontSize`, `lineHeight`, `letterSpacing`, and `paragraphSpacing`. The [font tokens]([[docsref:/design-tokens/font-tokens]]) combine these properties into text styles. Text case and text decoration have no typography tokens: a font token has neither unless it names one as a keyword, and only the link and expired roles of `font.context.*` name theirs.

### Token levels

Typography tokens have no levels. The scales of each family hold values of their own. The letter spacing of each weight, and the `html` and `context` groups, reference a size, a step of a scale, or another typography token, one token per weight, HTML element, or role. The `font.*` tokens are the next step: they reference the typography tokens property by property.

A brand gives the text its character by overriding the font families and the font weights in its own token set. It retunes an HTML element or a [context role](#context-roles) by overriding the tokens of the `html` or `context` group. Where the token system has the optional `screen` group, each screen has a token set that holds `typography.fontSize.website.*`. No theme and no app of the committed configuration overrides a typography token.

<CxTable>
| Tokens | Token set |
| --- | --- |
| `typography.fontFamily.*`, `typography.fontWeight.*` | `source/base/brand-base.json`, overridden by the `brand-base.json` of a brand, such as `source/brand-chassis/brand-base.json` |
| `typography.fontSize.*`, `typography.lineHeight.*`, `typography.letterSpacing.*`, `typography.paragraphSpacing.*` | `source/base/brand-base.json` |
| `typography.fontSize.website.*` | The token set of each screen, such as `source/screen-website/screen-large.json` |
</CxTable>

## Font families

A font family token holds a list of font families: the font of the brand first, then its fallbacks. The font tokens of a group take their family from the token of the same name.

<CxTable>
| Token | Purpose |
| --- | --- |
| `typography.fontFamily.text` | The font family of the brand for running text and for the text of components: `font.text.*`, `font.website.*`, and the families of the `html` and `context` groups except `code` |
| `typography.fontFamily.display` | The font family of the brand for display text: `font.display.*` |
| `typography.fontFamily.code` | The font family of the brand for code: `font.code.*`, and the `code` families of the `html` and `context` groups |
| `typography.fontFamily.icon` | The font family of the icon font |
</CxTable>

The `html` group holds one family per group of HTML elements, with the same names as the weights in `typography.fontWeight.html.*`. `typography.fontFamily.html.heading` is the family of `font.html.h1` to `font.html.h6`, and each other family belongs to the element of its name. A brand sets a group of elements in another family by overriding its reference, as the `sinefil` brand does with `{typography.fontFamily.display}` for every group except `code`.

<CxTable>
| Token | Reference |
| --- | --- |
| `typography.fontFamily.html.heading` | `{typography.fontFamily.text}` |
| `typography.fontFamily.html.body` | `{typography.fontFamily.text}` |
| `typography.fontFamily.html.paragraph` | `{typography.fontFamily.text}` |
| `typography.fontFamily.html.blockquote` | `{typography.fontFamily.text}` |
| `typography.fontFamily.html.list` | `{typography.fontFamily.text}` |
| `typography.fontFamily.html.cite` | `{typography.fontFamily.text}` |
| `typography.fontFamily.html.code` | `{typography.fontFamily.code}` |
</CxTable>

The `context` group holds references too, one family per role of `font.context.*`. Every size of a role shares the family of the role: `typography.fontFamily.context.title` is the family of `font.context.title.medium`, `font.context.title.large`, and `font.context.title.small`.

<CxTable>

| `typography.fontFamily.context.hero` | `{typography.fontFamily.text}` |

The committed brands override `typography.fontFamily.text`, `typography.fontFamily.display`, and `typography.fontFamily.code`, and the `sinefil` brand overrides the `html` group too. `typography.fontFamily.icon` is the same in every brand.

## Font weights

Font weight tokens name the weights of a family by role, not by weight. They follow the pattern `typography.fontWeight.<family>.<role>`: the families `text` and `display` have the roles `normal`, `strong`, `mass`, and `elegant`, and the family `code` has `normal` and `strong`. Each holds the weight that the brand gives to the role, so `typography.fontWeight.text.strong` can be a heavier weight in one brand than in another.

The value of a font weight token is the style name that the font has in Figma. A style name can name a weight and a style, such as an italic. The build splits every font weight token into two tokens, `<token>.weight` and `<token>.style`: `typography.fontWeight.text.strong` becomes `typography.fontWeight.text.strong.weight` and `typography.fontWeight.text.strong.style`. A style name that names no style gets the style `normal`.

Fonts spell their style names in their own way, so the same weight can be written with or without a space in two token sets. The build reads both spellings as the same weight.

The weights of the HTML elements reference the roles of the text family, so they follow the brand. The table shows the weights that `font.html.*` uses.

<CxTable>
| Token | Reference | Purpose |
| --- | --- | --- |
| `typography.fontWeight.html.code` | `{typography.fontWeight.text.normal}` | Weight of `font.html.code` |
| `typography.fontWeight.html.body` | `{typography.fontWeight.text.normal}` | Weight of `font.html.body` |
| `typography.fontWeight.html.paragraph` | `{typography.fontWeight.text.normal}` | Weight of `font.html.paragraph` |
| `typography.fontWeight.html.heading` | `{typography.fontWeight.text.mass}` | Weight of the headings, `font.html.h1` to `font.html.h6` |
| `typography.fontWeight.html.cite` | `{typography.fontWeight.text.strong}` | Weight of `font.html.cite` |
| `typography.fontWeight.html.list` | `{typography.fontWeight.text.normal}` | Weight of `font.html.list` |
| `typography.fontWeight.html.bold` | `{typography.fontWeight.text.mass}` | Bold text inside an element; no font token references it |
</CxTable>

`typography.fontWeight.html.blockquote` holds a style name of its own, with an italic style. It is the weight of `font.html.blockquote`.

The weights of the context roles are in the group `typography.fontWeight.context.*`, one token per role, shared by the sizes of the role. They reference a role of the text family, or of the code family for the code roles; [Context roles](#context-roles) lists them.

## Font sizes

A font size token holds a size in design pixels. The tokens follow the pattern `typography.fontSize.<group>.<step>`. The scales hold sizes of their own, and the `context` group and some of the website tokens hold a reference.

<CxTable>
| Tokens | Steps |
| --- | --- |
| `typography.fontSize.text.*` | `5xlarge`, `4xlarge`, `3xlarge`, `2xlarge`, `xlarge`, `large`, `medium`, `small`, `xsmall`, `2xsmall` |
| `typography.fontSize.display.*` | The steps of the text family |
| `typography.fontSize.code.*` | `large`, `medium`, `small` |
| `typography.fontSize.html.*` | The name of an HTML element, such as `h1` or `paragraph` |
| `typography.fontSize.context.*` | The name of a context role and its size, such as `heading` or `title-medium` |
| `typography.fontSize.website.*` | The part of a website section, such as `hero-title` |
</CxTable>

Each step of a scale is larger than the step after it in the list, from `5xlarge` down to `2xsmall`.

`typography.fontSize.website.*` are the only typography tokens that differ per screen. The token set of each screen holds all of them, so a screen can reference another step of the text scale. `typography.fontSize.website.hero-title` and `typography.fontSize.website.section-title` hold a size of their own on every screen. The others hold a reference.

<CxTable>
| Token | `large` | `medium` | `small` |
| --- | --- | --- | --- |
| `typography.fontSize.website.hero-body` | `{typography.fontSize.text.xlarge}` | `{typography.fontSize.text.large}` | `{typography.fontSize.text.large}` |
| `typography.fontSize.website.section-body` | `{typography.fontSize.text.xlarge}` | `{typography.fontSize.text.large}` | `{typography.fontSize.text.medium}` |
| `typography.fontSize.website.feature-title` | `{typography.fontSize.text.xlarge}` | `{typography.fontSize.text.large}` | `{typography.fontSize.text.large}` |
| `typography.fontSize.website.feature-body` | `{typography.fontSize.text.large}` | `{typography.fontSize.text.medium}` | `{typography.fontSize.text.medium}` |
| `typography.fontSize.website.module-title` | `{typography.fontSize.text.large}` | `{typography.fontSize.text.medium}` | `{typography.fontSize.text.medium}` |
</CxTable>

## Line heights

A line height token holds the line height of the font size with the same name, in design pixels: `typography.lineHeight.text.medium` belongs to `typography.fontSize.text.medium`. The groups `text`, `display`, `code`, and `html` have a line height for each of their font sizes, and every line height is larger than its font size. The `context` group has one for each of its font sizes except `jumbo` and `hero`, whose font tokens hold a percentage instead.

The website has no line height tokens. `font.website.*` holds its line heights as a percentage of the font size, so they follow the font size of the screen.

## Letter spacing

Letter spacing tokens hold the space between letters, and they are in `source/base/brand-base.json`, so a brand can change them. The families `text` and `display` have one letter spacing per weight, `typography.letterSpacing.<family>.<weight>`, and a base token of each size references the letter spacing of its weight: `font.text.medium.strong` references `{typography.letterSpacing.text.strong}`. ## Paragraph spacing

Paragraph spacing tokens hold the space after a paragraph, as a size in design pixels. They are in `source/base/brand-base.json`, so a brand can change them. Each step from `small` to `large` is larger than the one before.

<CxTable>
| Token | Purpose |
| --- | --- |
| `typography.paragraphSpacing.base.zero` | No space: every font token that the other steps do not name |
| `typography.paragraphSpacing.base.small` | The `small` step of `font.context.title.*`, `font.context.body.*`, and `font.context.highlight.*` |
| `typography.paragraphSpacing.base.medium` | The `medium` step of the same groups, and `font.html.paragraph` |
| `typography.paragraphSpacing.base.large` | The `large` step of the same groups, and `font.context.heading` |
</CxTable>

## Usage

Set text with a [font token]([[docsref:/design-tokens/font-tokens]]), which holds every property of a text style. Use a typography token where one property is needed on its own: `typography.fontFamily.text` for the font family of a page, `typography.fontWeight.text.strong` for emphasis inside a text.

Take the font size and the line height from the same step. `typography.lineHeight.text.large` is made for `typography.fontSize.text.large`, and the web output of a line height is relative to the font size of its step.

Give a brand its own fonts by overriding `typography.fontFamily.*` and `typography.fontWeight.*` in the token set of the brand. Every font token follows, because the font tokens hold references. An override can be a reference too. `source/brand-sinefil/brand-base.json` sets every group of HTML elements except `code` in the display family:

```json
{
  "typography": {
    "fontFamily": {
      "html": {
        "heading": {
          "$type": "fontFamilies",
          "$value": "{typography.fontFamily.display}"
        },
        "body": {
          "$type": "fontFamilies",
          "$value": "{typography.fontFamily.display}"
        },
        "paragraph": {
          "$type": "fontFamilies",
          "$value": "{typography.fontFamily.display}"
        },
        "blockquote": {
          "$type": "fontFamilies",
          "$value": "{typography.fontFamily.display}"
        },
        "list": {
          "$type": "fontFamilies",
          "$value": "{typography.fontFamily.display}"
        },
        "cite": {
          "$type": "fontFamilies",
          "$value": "{typography.fontFamily.display}"
        }
      }
    }
  }
}
```

A weight names a style of one family, so a brand that moves a group of elements to another family also points the weight and the letter spacing of that group at those of that family, such as `{typography.letterSpacing.display.mass}` for `typography.letterSpacing.html.heading`. The `sinefil` brand points `typography.fontWeight.html.heading` at `{typography.fontWeight.display.strong}` for its headings.

Retune a context role in the same way. Override a token of the `context` group to give a role another step, weight, or family: `typography.fontSize.context.heading` with another step of the text scale changes `font.context.heading`, and no font token has to change.

In the same way, a brand that overrides the family of a role also points the weight and the letter spacing of that role at those of the same family. To set `font.context.hero` in the display family, override the family, the weight, and the letter spacing of `hero` together:

```json
{
  "typography": {
    "fontFamily": {
      "context": {
        "hero": {
          "$type": "fontFamilies",
          "$value": "{typography.fontFamily.display}"
        }
      }
    },
    "fontWeight": {
      "context": {
        "hero": {
          "$type": "fontWeights",
          "$value": "{typography.fontWeight.display.mass}"
        }
      }
    },
    "letterSpacing": {
      "context": {
        "hero": {
          "$type": "letterSpacing",
          "$value": "{typography.letterSpacing.display.mass}"
        }
      }
    }
  }
}
```

A role with several sizes shares one family, one weight, and one letter spacing, so one override changes every size: `typography.fontFamily.context.title`, `typography.fontWeight.context.title`, and `typography.letterSpacing.context.title` set `font.context.title.medium`, `font.context.title.large`, and `font.context.title.small`.

Write a font weight as the font names it in Figma, and keep that spelling. `pnpm tokens:lint:source` reports a weight that the build does not know.

## Platform output

Line heights, font sizes, and paragraph spacing print as sizes, each platform in its own unit. The other properties print as numbers and strings.

<CxTable>
| Platform | Name | Format |
| --- | --- | --- |
| Web | `$cx-typography-line-height-text-medium` | A number in `em` |
| iOS | `TypographyLineHeightTextMedium` | A `CGFloat` in points |
| Android | `@dimen/typography_line_height_text_medium` | A `<dimen>` in `sp` |
</CxTable>

The web divides a line height by the font size of the same name, so the line height is relative to the font size. iOS and Android print the line height as a size.

The other properties have these formats.

<CxTable>
| Tokens | Web | iOS | Android |
| --- | --- | --- | --- |
| `typography.fontFamily.*` | The list of families, as the token holds it | A string with the first family of the list | A `<string>` with the first family of the list |
| `typography.fontWeight.*.weight` | A number from `100` to `900` | A case of `UIFont.Weight` | An `<integer>` from `100` to `900` |
| `typography.fontWeight.*.style` | A keyword | A string | A `<string>` |
| `typography.fontSize.*` | A size in `rem` | A `CGFloat` in points | A `<dimen>` in `sp` |
| `typography.letterSpacing.*` | A number in `em`: the design pixels divided by 16 | A `CGFloat` in points | An `<item>` of the type `dimen` with the format `float`, in design pixels |
| `typography.paragraphSpacing.*` | A size in `rem` | A `CGFloat` in points | A `<dimen>` in `sp` |
</CxTable>

The build prints the two tokens of a font weight under their own names, such as `$cx-typography-font-weight-text-strong-weight` and `$cx-typography-font-weight-text-strong-style` on the web.

The web writes the families and weights to `string.scss`, and the sizes, line heights, and spacings to the number file of each screen; `main.scss` holds all of them. iOS and Android split the tokens the same way between their string and number files.

See the [web]([[docsref:/use-in-project/web-applications]]), [iOS]([[docsref:/use-in-project/ios-applications]]), and [Android]([[docsref:/use-in-project/android-applications]]) docs for the files that hold these names.
