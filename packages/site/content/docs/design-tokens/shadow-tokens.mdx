## Introduction

Shadow tokens hold the shadows of elements: the offset, blur, spread, and color of each layer, and whether the layer falls outside or inside the element. The values on this page are those of the `chassis` brand and the `light` theme. The sizes of a shadow are the same in every brand, theme, and screen; the colors change with the brand and the theme.

### Token levels

The shadow category has the three token levels, in two token sets. `packages/tokens/source/base/effect-base.json` holds the base tokens, and `packages/tokens/source/base/app-base.json` holds the context and component tokens.

- **Base tokens** hold the layers: `shadow.elevation.*`, `shadow.glow.*`, and `bg-blur.*`. Their colors reference the shadow colors `color.shadow.*`.
- **Context tokens** name a shadow by its size or by the state of an element: `shadow.context.*`.
- **Component tokens** assign a shadow to a component: `shadow.<component>.*`.

The shadow of a card passes through every level:

```text
shadow.card.main               {shadow.context.medium}
shadow.context.medium          {shadow.elevation.default.20}
shadow.elevation.default.20    two layers, each with the color {color.shadow.default}
color.shadow.default           {color.base.shadow.light.default}
```

### Shadow layers

A shadow token has the type `boxShadow`, and its value is one layer or a list of layers. `shadow.elevation.default.10` in `packages/tokens/source/base/effect-base.json` has two layers:

```json
{
  "shadow": {
    "elevation": {
      "default": {
        "10": {
          "$type": "boxShadow",
          "$value": [
            {
              "color": "{color.shadow.default}",
              "type": "dropShadow",
              "x": "{dimension.base.0}",
              "y": "{dimension.base.2}",
              "blur": "{dimension.base.8}",
              "spread": "{dimension.base.n2}"
            },
            {
              "color": "{color.shadow.default}",
              "type": "dropShadow",
              "x": "{dimension.base.0}",
              "y": "{dimension.base.1}",
              "blur": "{dimension.base.4}",
              "spread": "{dimension.base.n1}"
            }
          ]
        }
      }
    }
  }
}
```

Each layer has the same six keys, and a token with one layer may hold the layer without the list.

<CxTable>
| Key | Holds |
| --- | --- |
| `color` | The color of the layer |
| `type` | `dropShadow` for a shadow outside the element, `innerShadow` for a shadow inside it |
| `x` | The horizontal offset |
| `y` | The vertical offset |
| `blur` | The blur of the layer |
| `spread` | The size that the layer gains, or loses when the value is negative |
</CxTable>

The sizes reference `dimension.base.*`: `{dimension.base.8}` is `8px`, `{dimension.base.n2}` is `-2px`, and `{dimension.base.d25}` is `2.5px`. The build renames `x` and `y` to `offsetX` and `offsetY`, which is where the names of the iOS and Android output come from.

## Base tokens

The base tokens hold layers with sizes and colors, and the other levels reference them. The shadow colors belong to the color category and are listed here because every elevation token references one.

### Elevation

Elevation tokens are named `shadow.elevation.<context>.<level>`, with eleven contexts and eleven levels. The levels are `05`, `10`, `20`, `30`, `40`, `50`, `60`, `70`, `80`, `90`, and `95`; the source and the generated files list `05` last.

The `default` context has two layers per level, both with the color `{color.shadow.default}`. In the first layer the blur is four times the vertical offset and the spread is the negative offset; the second layer has half the sizes of the first.

Each value lists the layers in the order of the source, and each layer as x, y, blur, spread, and color. The other contexts have the sizes of `default` at every level and differ in their colors:

- `alternate` has the same two layers with the color `{color.shadow.alternate}`.
- `primary`, `secondary`, `neutral`, `danger`, `success`, `warning`, and `info` add a third layer to the two layers of `default`. It has the sizes of the first layer and the color `{color.shadow.<context>}`.
- `brand` and `accent` add the same third layer with the colors `{color.primitive.brand.t-5020}` and `{color.primitive.accent.t-5020}`.

`shadow.elevation.primary.10`, for example, is `0px 2px 8px -2px rgba(0, 0, 0, 0.1), 0px 1px 4px -1px rgba(0, 0, 0, 0.1), 0px 2px 8px -2px rgba(0, 164, 204, 0.4)`.

## Context tokens

`shadow.context.*` names a shadow by its size (`none`, `small`, `medium`, `large`, `inset`) or by the state of an element (`idle`, `disabled`, `hover`, `press`, `focus`, `highlight`). Reach for these tokens in components that have no shadow token of their own.

## Component tokens

Component tokens assign a shadow to a component or to one of its states. All of them are in `packages/tokens/source/base/app-base.json`, and all but one reference a context token.

## Usage

Choose a shadow token by its level, then by its size or state. The theme and the brand set its colors.

### Choosing a level

Use the component token when the component has one: `shadow.card.main` for a card, `shadow.modal.main` for a modal. Use `shadow.context.small`, `shadow.context.medium`, or `shadow.context.large` for an element without a token of its own; they are the levels `10`, `20`, and `40` of `shadow.elevation.default.*`.

For an element that changes its shadow with its state, use the state tokens: `shadow.context.idle` and `shadow.context.disabled` hold no shadow, `shadow.context.hover` holds level `20`, and `shadow.context.press` holds level `10`. Use `shadow.elevation.*` directly for a level that the context tokens don't name, or for a shadow with a colored layer such as `shadow.elevation.primary.20`.

### Themes and brands

Only the colors of a shadow change with the theme. `shadow.context.medium` is `0px 4px 16px -4px rgba(0, 0, 0, 0.4), 0px 2px 8px -2px rgba(0, 0, 0, 0.4)` in the dark theme, because `color.shadow.default` is `rgba(0, 0, 0, 0.4)` there. Tokens without a color of the theme keep their value: the glows, the background blurs, `shadow.nav-left.main`, and `shadow.context.none` with the tokens that reference it.

The `sinefil` brand has its own colors for the glows other than `shadow.glow.black` and `shadow.glow.white`, the background blurs, `shadow.context.focus`, `shadow.context.highlight`, and the third layer of the elevation tokens. `color.shadow.primary`, for example, is `rgba(122, 46, 111, 0.4)` in the `sinefil` brand.

## Platform output

The web prints a shadow token as one CSS `box-shadow` value with sizes in `rem`. iOS and Android split it into one constant or resource per part of each layer, with sizes in points on iOS and in `dp` on Android.

<CxTable>
| Platform | Name | Value |
| --- | --- | --- |
| Web | `$cx-shadow-card-main` | `var(--box-shadow-md)` |
| iOS | `ShadowCardMain1Blur` | `CGFloat(16)` |
| Android | `@dimen/shadow_card_main_1_blur` | `16dp` |
</CxTable>

The web row is the whole shadow of `shadow.card.main`; the iOS and Android rows are the blur of its first layer.

On the web, the build writes each layer as x, y, blur, spread, and color, adds `inset` to an inner shadow, and separates the layers with a comma:

```scss
$cx-shadow-context-medium: 0rem 0.25rem 1rem -0.25rem rgba(0, 0, 0, 0.1), 0rem 0.125rem 0.5rem -0.125rem rgba(0, 0, 0, 0.1) !default;
$cx-shadow-context-inset: 0rem 0.125rem 0.25rem 0rem rgba(0, 0, 0, 0.1) inset !default;
$cx-shadow-button-idle: 0rem 0rem 0rem 0rem rgba(0, 0, 0, 0) !default;
$cx-shadow-card-main: var(--box-shadow-md) !default;
```

A token whose value is a reference to `shadow.context.<name>` prints `var(--box-shadow-<name>)`, a custom property of [Chassis CSS](https://github.com/chassis-ui/css), with `sm`, `md`, and `lg` for `small`, `medium`, and `large`. Tokens named after a state (`idle`, `hover`, `press`, `disabled`, `focus`, `highlight`) print their value instead, which is why `$cx-shadow-button-idle` holds a value. The presets `web-scss`, `web-px`, and `web-vw` print the value of every shadow token, in `rem`, `px`, and `vw`.

The web build writes the shadow tokens to `main.scss` only, with the colors of the light theme. `color-light.scss` and `color-dark.scss` hold `$cx-color-shadow-default` and the other shadow colors of each theme.

<Callout type="warning">
Level `05` of every elevation context except `default` has the spread `-0.5` without a unit in the source. The web prints it as it is, as in `$cx-shadow-elevation-primary-05`, and a browser rejects a `box-shadow` with a length that has no unit. iOS and Android print `CGFloat(-0.5)` and `-0.5dp`.
</Callout>

On iOS, the build writes the parts `Color`, `Type`, `Blur`, `Radius`, `Spread`, `OffsetX`, and `OffsetY`. The number of the layer follows the name of the token when the token has more than one layer, so `ShadowElevationDefault101Blur` is the blur of layer `1` of level `10`. `Radius` is half the blur, for the `shadowRadius` of Core Animation, which has no equivalent of the spread.

```swift
    public static let ShadowCardMain1Color = UIColor(red: 0.000, green: 0.000, blue: 0.000, alpha: 0.1)
    public static let ShadowCardMain1Type = "dropShadow"
    public static let ShadowCardMain1Blur = CGFloat(16)
    public static let ShadowCardMain1Radius = CGFloat(8)
    public static let ShadowCardMain1Spread = CGFloat(-4)
    public static let ShadowCardMain1OffsetX = CGFloat(0)
    public static let ShadowCardMain1OffsetY = CGFloat(4)
```

On Android, the build writes the same parts without the radius, as `<color>`, `<string>`, and `<dimen>` resources:

```xml
  <color name="shadow_card_main_1_color">#1a000000</color>
  <string name="shadow_card_main_1_type">dropShadow</string>
  <dimen name="shadow_card_main_1_blur">16dp</dimen>
  <dimen name="shadow_card_main_1_spread">-4dp</dimen>
  <dimen name="shadow_card_main_1_offset_x">0dp</dimen>
  <dimen name="shadow_card_main_1_offset_y">4dp</dimen>
```

The parts of a shadow go to the file of their type. The colors of both themes are in the color files, where `ShadowCardMain1Color` has an alpha of `0.4` in `ColorDark.swift` and `shadow_card_main_1_color` is `#66000000` in `res/values-night/color.xml`. The sizes are in the number files and the types in the string files.

<Callout type="warning">
The color parts of `shadow.context.*` are in the color files only. `ChassisTokens.swift` and `main.xml` hold the sizes and the type of `ShadowContextSmall1` and `shadow_context_small_1`, but not the color.
</Callout>

See the [web]([[docsref:/use-in-project/web-applications]]), [iOS]([[docsref:/use-in-project/ios-applications]]), and [Android]([[docsref:/use-in-project/android-applications]]) docs for the files that hold these names.
