## Introduction

Size tokens hold the dimensions of an element: the height of a button, the size of an icon, the width of a modal window. The whitespace inside and between elements belongs to the [space tokens]([[docsref:/design-tokens/space-tokens]]), whose page has the same sections as this one.

The values are design pixels, and the build converts them to the unit of each platform, as [Platform output](#platform-output) shows. A size token holds the same value for every brand, app, and theme of the configuration. Only the tokens of `size.website.*` change with the screen.

### Token levels

Each level references the level below it, so a pixel value is written once, in `dimension.base.*`. The chain of `16px` shows the three levels:

```text
dimension.base.16                  16px
└── size.unit.16                   {dimension.base.16}
    ├── size.context.2xsmall       {size.unit.16}
    ├── size.icon.glyph.xsmall     {size.unit.16}
    └── size.button.small-caret    {size.unit.16}
```

Context and component tokens both reference `size.unit.*`. No component token references `size.context.*`, so a change to `size.context.medium` leaves `size.button.medium-main` as it is. The token sets of each level are files of `packages/tokens/source/`:

<CxTable>
| Level | Tokens | References | Token set |
| --- | --- | --- | --- |
| Base | `dimension.base.*` | None | `base/metric-source.json` |
| Base | `size.unit.*` | `dimension.base.*` | `base/metric-base.json` |
| Context | `size.context.*`, `size.icon.glyph.*`, `size.asset.*` | `size.unit.*` | `base/app-base.json` |
| Component | `size.<component>.*` | `size.unit.*` | `base/app-base.json` |
| Component | `size.website.*` | `size.unit.*` | `screen-website/screen-<screen>.json` |
</CxTable>

## Base tokens

The base level has two groups. `dimension.base.*` holds the pixel values, and `size.unit.*` references them one to one under the name of the category.

### Dimension scale

`dimension.base.*` names a step by its pixel value: `dimension.base.16` holds `16px`. The steps go from `0` to `10` by 1, from `12` to `32` by 2, from `36` to `80` by 4, and from `88` to `136` by 8, followed by `160`, `192`, `256`, `320`, `512`, and `1024`. The size, space, border radius, and shadow tokens reference this scale.

Steps that are not a positive whole number have a prefix. `d` marks a fraction and `n` a negative value; the negative steps are `n1` to `n10`, `n12`, `n14`, `n16`, `n18`, `n20`, `n24`, `nd05`, `nd15`, and `nd25`. `dimension.base.scale` is not a step of the scale.

## Component tokens

Component tokens hold the sizes of the parts of one component. A component with sizes has a token per size and part, `size.<component>.<size>-<part>`, in the source order `medium`, `large`, `small`. The part `main` is the component itself; parts like `icon`, `caret`, and `avatar` are elements inside it. A component token references a step of `size.unit.*` unless its section names another reference.

## Usage

Size tokens apply to the width and the height of an element. The level to use depends on how specific the element is.

### Choosing a level

Use the most specific token that names the element, and go down a level only when none does:

- Use a component token for the part that it names: `size.button.medium-icon` for the icon of a medium button.
- Use `size.icon.glyph.*` for an icon and `size.context.*` for another element that has no component token.
- Use `size.unit.*` when no context token holds the value. The context scale ends at `64px`, and the unit scale goes on to `1024px`.
- Leave `dimension.base.*` to the token sets. It is in the output because the unit tokens reference it.

### Size and space

A size token sets a width or a height; a space token sets a padding or a gap. `size.unit.16` and `space.unit.16` hold the same value, because both reference `dimension.base.16`. The context tokens of both categories reference `size.unit.*`, so a change to `size.unit.16` changes `size.context.2xsmall` and `space.context.medium`.

## Platform output

Size tokens print in `rem` on the web, as `CGFloat` points on iOS, and as `dp` dimension resources on Android.

<CxTable>
| Platform | Name | Value |
| --- | --- | --- |
| Web | `$cx-size-context-medium` | `2.5rem` |
| iOS | `SizeContextMedium` | `CGFloat(40)` |
| Android | `@dimen/size_context_medium` | `40dp` |
</CxTable>

The web platform divides the pixels by 16, so `40px` prints `2.5rem` and `0px` prints `0rem`. A unit token with a fraction prints four decimals: `size.unit.05` holds `0.5px` and prints `0.0313rem`, while `dimension.base.05` prints `0.03125rem`. A value without a unit prints like a pixel value: `size.modal.window-small-w` holds `360` and prints `22.5rem`, `CGFloat(360)`, and `360dp`.

The build writes every level with its resolved value, `dimension.base.*` included. In `main.scss`:

```scss
$cx-dimension-base-16: 1rem !default;
$cx-size-unit-16: 1rem !default;
$cx-size-context-2xsmall: 1rem !default;
```

With the `outputReferences` option, a token names the token that it references, which is why `dimension.base.*` is in the output. The [Style Dictionary guide]([[docsref:/getting-started/style-dictionary]]) describes the option. With it, the build writes in `ChassisTokens.swift`:

```swift
    public static let DimensionBase16 = CGFloat(16)
    public static let SizeUnit16 = DimensionBase16
    public static let SizeContext2xsmall = SizeUnit16
```

The main file of each platform holds the values of the first configured screen, `large`. The values of `size.website.*` on another screen are in the number file of that screen. The build writes in `number-small.scss`:

```scss
$cx-size-website-section-thumb: 4rem !default;
```

See the [web]([[docsref:/use-in-project/web-applications]]), [iOS]([[docsref:/use-in-project/ios-applications]]), and [Android]([[docsref:/use-in-project/android-applications]]) docs for the files that hold these names.
