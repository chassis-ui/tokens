## Introduction

Border width tokens hold the thickness of the borders of components and of the lines that separate content. The values are the same in every brand, app, theme, and screen.

### Token levels

Border width tokens have two levels and no base level of their own. Context tokens (`borderWidth.context.*`) reference the [size scale]([[docsref:/design-tokens/size-tokens]]) `size.unit.*`, and component tokens (`borderWidth.<component>.*`) reference the context tokens. The border of an active form input resolves in four steps:

```text
borderWidth.form-input.active   {borderWidth.context.xlarge}
borderWidth.context.xlarge      {size.unit.2}
size.unit.2                     {dimension.base.2}
dimension.base.2                2px
```

Both levels are in `packages/tokens/source/base/app-base.json`.

## Context tokens

Context tokens name a border width by its size. They hold two series: a scale from `zero` to `2xlarge`, and the names `none`, `thin`, and `thick`, which have the values of `zero`, `small`, and `xlarge`. The component tokens reference the scale only.

<CxTable>
| Token | Value | Reference |
| --- | --- | --- |
| `borderWidth.context.none` | `0px` | `{size.unit.0}` |
| `borderWidth.context.thin` | `0.5px` | `{size.unit.05}` |
| `borderWidth.context.thick` | `2px` | `{size.unit.2}` |
| `borderWidth.context.zero` | `0px` | `{size.unit.0}` |
| `borderWidth.context.small` | `0.5px` | `{size.unit.05}` |
| `borderWidth.context.medium` | `1px` | `{size.unit.1}` |
| `borderWidth.context.large` | `1.5px` | `{size.unit.d15}` |
| `borderWidth.context.xlarge` | `2px` | `{size.unit.2}` |
| `borderWidth.context.2xlarge` | `4px` | `{size.unit.4}` |
</CxTable>

## Component tokens

Component tokens assign a border width to a component. Most components have one token, named `main`; form inputs and assets have more.

### Component borders

The `main` token of a component is the width of its border. Every one is `1px`, except the border of the section, which is `0px`.

### Form inputs

Form inputs have four border widths. The `active` and `floating` borders are `2px`, twice the width of the `regular` and `inactive` borders.

<CxTable>
| Token | Value | Reference |
| --- | --- | --- |
| `borderWidth.form-input.regular` | `1px` | `{borderWidth.context.medium}` |
| `borderWidth.form-input.floating` | `2px` | `{borderWidth.context.xlarge}` |
| `borderWidth.form-input.active` | `2px` | `{borderWidth.context.xlarge}` |
| `borderWidth.form-input.inactive` | `1px` | `{borderWidth.context.medium}` |
</CxTable>

### Assets

The asset tokens hold the thickness of the indicator and of the separator line. They reference the size tokens of the same assets, `size.asset.*`, and not the context tokens.

<CxTable>
| Token | Value | Reference |
| --- | --- | --- |
| `borderWidth.asset.indicator` | `4px` | `{size.asset.indicator}` |
| `borderWidth.asset.separator` | `1px` | `{size.asset.separator}` |
</CxTable>

## Usage

Use the token of the lowest level that fits the element.

- **A component with a token**: use its component token, `borderWidth.button.main` for the border of a button.
- **An element without a token**: use a step of `borderWidth.context.*`. `borderWidth.context.medium` is the `1px` border of nearly every component.
- **No border**: use `borderWidth.context.zero`, as `borderWidth.section.main` does.
- **A new component token**: reference a step of the scale (`zero` to `2xlarge`), as the existing component tokens do.

## Platform output

A border width prints as a custom property of Chassis CSS or a value in `rem` on the web, as a `CGFloat` in points on iOS, and as a `<dimen>` in `dp` on Android.

<CxTable>
| Platform | Name | Value |
| --- | --- | --- |
| Web | `$cx-border-width-button-main` | `var(--border-width-md)` |
| iOS | `BorderWidthButtonMain` | `CGFloat(1)` |
| Android | `@dimen/border_width_button_main` | `1dp` |
</CxTable>

The `web` platform prints the value of the context tokens, and a custom property for a component token that references a context token. The asset tokens reference a size token, so they print their value. The build writes these lines:

```scss
$cx-border-width-context-medium: 0.0625rem !default;
$cx-border-width-asset-indicator: 0.25rem !default;
$cx-border-width-button-main: var(--border-width-md) !default;
```

The custom property is named after the referenced step in its short form: `md` for `medium` and `xl` for `xlarge`, while `zero` keeps its name. Chassis CSS declares these custom properties, so the files of the `web` platform work with Chassis CSS only. The presets `web-scss`, `web-px`, and `web-vw` print the value of every token; see [the Style Dictionary guide]([[docsref:/getting-started/style-dictionary]]).

The widths of half a pixel lose precision on the web: `borderWidth.context.small` is `0.5px` and prints as `0.0313rem`, and `borderWidth.context.large` is `1.5px` and prints as `0.0938rem`. iOS and Android keep the number, as `CGFloat(0.5)` and `0.5dp`.

See the [web]([[docsref:/use-in-project/web-applications]]), [iOS]([[docsref:/use-in-project/ios-applications]]), and [Android]([[docsref:/use-in-project/android-applications]]) docs for the files that hold these names.
