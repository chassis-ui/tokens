## Introduction

Chassis Tokens holds the design tokens of the Chassis Design System and the build that turns them into files for the web, iOS and Android. The tokens are JSON files in [Tokens Studio](https://tokens.studio) format, synced with Figma. The build uses [Style Dictionary](https://styledictionary.com) and writes SCSS variables, Swift constants and Android resources.

The output is committed to the repository and published, so you can install the tokens without building them. [Chassis CSS](https://github.com/chassis-ui/css) is built on the web output.

You can also own the tokens: fork the repository, change the token sets, and build your own brands, apps and platforms. The [quick start]([[docsref:/getting-started/quick-start]]) covers both ways.

## Token sets

A token set is one JSON file of `packages/tokens/source/`, such as `base/theme-dark.json`. `packages/tokens/source/$themes.json` has four groups, and each option of a group selects the token sets that hold its tokens.

<CxTable>
| Group | Options | Token sets of an option hold |
| --- | --- | --- |
| `brand` | `default`, `chassis`, `sinefil`, `demo-a`, `demo-b` | The palette, the font families and weights, and the base border radius |
| `app` | `docs`, `demo` | The component tokens, with the overrides of the app |
| `theme` | `light`, `dark` | The primitive and context colors, and the shadows |
| `screen` | `large`, `medium`, `small` | The font sizes, and the sizes and spacing of the website layout |
</CxTable>

One option of each group makes a list of token sets, named `<brand>_<app>_<theme>_<screen>`, such as `chassis_docs_light_large`. A token set overrides the tokens of the sets before it in the list, as in Tokens Studio: the `dark` theme selects `base/theme-base.json` and then `base/theme-dark.json`, whose colors replace those of the first.

The [Tokens Studio guide]([[docsref:/getting-started/tokens-studio]]) describes the token sets and how to change them, and the [Figma Variables guide]([[docsref:/getting-started/figma-variables]]) how they become Variables in Figma.

## Token levels

Tokens reference each other on three levels, so a change to a base token reaches every token that references it.

<CxTable>
| Level | Holds | Example | Value |
| --- | --- | --- | --- |
| Base tokens | Raw values | `size.unit.16` | `16px` |
| Context tokens | A value named by its role | `space.context.medium` | `{size.unit.16}` |
| Component tokens | A value for a part of a component | `space.button.medium-gap` | `{space.unit.8}` |
</CxTable>

The pages of the token categories, such as the [space tokens]([[docsref:/design-tokens/space-tokens]]) and the [color tokens]([[docsref:/design-tokens/color-tokens]]), list the tokens of each level.

## Build output

The build reads `chassis.build` of `packages/tokens/package.json`, which lists the brands, themes, screens and apps to build, and the platforms of each app. The committed configuration builds the brands `chassis` and `sinefil`, the app `docs` for the `web` platform, and the app `demo` for the `ios` and `android` platforms. The other options of the `brand` group are not built.

Every app and brand gets one folder per platform, `packages/tokens/dist/<platform>/<app>/<brand>/`.

<CxTable>
| Platform | Folder | Files |
| --- | --- | --- |
| `web` | `dist/web/docs/<brand>/` | SCSS variables: `main.scss`, `string.scss`, one color file per theme and one number file per screen |
| `ios` | `dist/ios/demo/<brand>/` | Swift constants with UIKit values: `ChassisTokens.swift`, `String.swift`, one color file per theme and one number file per screen; `Color.swift`, whose colors follow the light and dark appearance; the icons in `Icons.xcassets` |
| `android` | `dist/android/demo/<brand>/` | XML resources: `main.xml`, `string.xml`, one color file per theme and one number file per screen; the same resources as a `res/` tree with night and screen-size qualifiers, and the icons as vector drawables |
</CxTable>

A token keeps its name on every platform, in the spelling of the platform, and its value gets the unit of the platform.

<CxTable>
| Platform | Name | Value |
| --- | --- | --- |
| Web | `$cx-space-context-medium` | `1rem` |
| iOS | `SpaceContextMedium` | `CGFloat(16)` |
| Android | `@dimen/space_context_medium` | `16dp` |
</CxTable>

The `web` platform writes SCSS for Chassis CSS: `$cx-color-accordion-item-fg-color` is `var(--default-fg-main)`, the custom property that Chassis CSS generates for `color.context.default.fg-main`. The presets `web-scss`, `web-px` and `web-vw` write SCSS variables without custom properties for other CSS frameworks, and the presets `ios-swiftui` and `android-compose` write SwiftUI and Jetpack Compose values. No preset is part of the committed configuration; you select one when you build your own tokens. The [Style Dictionary guide]([[docsref:/getting-started/style-dictionary]]) is the reference of the build.

## Packages

Three packages hold files of `packages/tokens/dist/`: an npm package, a Swift package and an Android library. The current version is [[config:current_version]].

<CxTable>
| Package | Name | Contents |
| --- | --- | --- |
| npm package | `@chassis-ui/tokens` | All of `dist/`: the web, iOS and Android folders of both brands |
| Swift package | `[[config:repo]].git`, with the libraries `ChassisTokensDemoChassis` and `ChassisTokensDemoSinefil` | The Swift files and the icons of `dist/ios/demo/<brand>/` |
| Android library | `chassis-tokens-demo-<brand>-<version>.aar`, attached to the [GitHub release]([[config:repo]]/releases) | The `res/` tree of `dist/android/demo/<brand>/` |
</CxTable>
